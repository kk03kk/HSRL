# 评测标准与判胜规则

本文保留 M1/M2、名次和协议对齐的项目口径，并记录旧基线的比较方法。具体样本量、对手场、动作预算和判据查相应冻结计划与回执。现任 3286 的正式场见 [Player150 五轮评测](analysis/PLAYER150_FINAL_REVIEW_20261121.md)，状态见[项目状态](PROJECT_STATE.md)。

## 1. 过程指标与名次

以下引用记录 2026-11-14 的旧场口径。现行综合判读见 §5，具体评测剂量按对应冻结计划。

> **主判据（用户 2026-11-14 定）：逐回合中位战力 M1。** 同场同 seed 下，M1 更高的模型更强 ——
> 本轮数据支持这一点（候选 T8–T18 板面全面更高 +1%~+19%，名次同步更好 2.615→2.352；
> 反过来冠军 tier 高 0.5~0.7 级却打得差）。名次面板继续**并列显示**做交叉检查，
> 但不再当门槛（它跟评测一起免费产出，不额外消耗时间）。
>
> **评测频次：每轮训练只跑一次**（512 局 / 1 张卡 / 约 11 分钟）。
> **默认用没见过的 held-out 场**：成本和训练场一样，但顺手去掉"主场优势"这个隐患。
> （2026-11-14 曾为验证这个隐患跑了两次，结论是影响很小：−0.264 vs −0.281，所以以后不必再跑两次。）

| 尺子 | 回答什么问题 | 用途 |
|---|---|---|
| **过程刻度（M1 / M2）** | 模型在第 N 回合的**实力**有没有长进 | **主判据**；也是校准战团库的输入 |
| **结果刻度（名次面板）** | 打完 8 人局排第几 | 交叉检查（免费附带） |

**永远不要**用过程刻度宣布"棋力提升"，也不要用名次掩盖"过程退化"。两者都报。

## 2. M1 / M2 的精确定义

| 指标 | 定义 | 口径要求 |
|---|---|---|
| **M1 逐回合中位战力** | 每个回合"**战斗开始前**"己方战团 `Σ(攻 + 生命)`，在该回合所有对局上的**中位数** | ① 必须是"先求和再取中位"，**禁止**把"攻击中位数 + 生命中位数"相加冒充；② 逐回合列出 turn 1 → 最后；③ 每回合必须报样本量 `n` |
| **M2 逐回合平均 tier** | 同一时点的 tavern tier 均值 | 逐回合列出 |

数据来源：`workflows/eval_human_gap.py` 产出的 `panel.json` → `models[0].curves[turn]`，字段 `strength_p50`（= M1）与 `tier_mean`（= M2）。该函数的取数口径是"招募结束时的战团 = 人家战团库所说的 combat_start"，与人类数据同口径。

辅助字段（只作诊断，不作结论）：`strength_p90`、`board_n_p50`、`tier5plus_share`、`tier_hist`。

### 2.1 第三个指标：6 本停留回合数（2026-11-15 加）

用强制升本训练时，光看"到 6 本多早"不够——**到得早但活不久等于没经验**。所以加一个：

```
6 本回合数/局 = Σ_回合 [该回合 tier ≥ 6 的局数] ÷ 总局数
```

数据来源：`panel.json → curves[turn].tier_hist`（把 `"6"` 与 `"7"` 的计数相加）。
口径是"**平均每局有多少个回合处于 6 本及以上**"。

参考值：v5 ≈ 5.2，**v6 = 7.36**。

### 2.2 标准对比表格式（用户 2026-11-15 规定，**所有轮次汇报必须用这个格式**）

**表 1：逐回合对比**（**必须从第 1 回合开始，逐回合列全，不许跳行/省略**）

| 回合 | 训练前模型中位战力 | 训练后模型中位战力 | 差值 | 训练前模型平均酒馆等级 | 训练后模型平均酒馆等级 | 差值 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | … | … | ±x.x% | … | … | ±x.xx |
| 2 | … | … | … | … | … | … |
| … | | | | | | |

- 「训练前模型」= 本轮起点 / 对照模型；「训练后模型」= 本轮产物。
- **战力差值用百分比**（`(后−前)/前`），**tier 差值用绝对差**（`后−前`，两位小数）。
- 表头顺序固定：先"战力三列"，再"tier 三列"。

**表 2：终局阵容随从统计**（两个模型各一份）

必须包含：
1. 平均终局阵容规模（随从数）、平均终局战力；
2. **卡牌 tier 构成**（T1–T7 各占百分比）；
3. **种族构成**（按出现次数排序）；
4. **Top 15 随从**：中文名 + tier + 种族 + 出现率（占对局比例）。

**表 3（辅助，不替代表 1）**：`mean_rank` / 前四率 / 吃鸡率 / 非法动作数 / 截断局数。

> 若两个模型面对的场地或强制升本设置不同，**必须在表头注明**，否则数字不可直接比较。

## 3. 名次面板（判胜尺子）

| 统计 | 说明 |
|---|---|
| `mean_rank` | 平均名次（1 最好，8 最差） |
| `top4_rate` | 前四率 |
| `win_rate` | 吃鸡率 |
| `illegal_actions` | 必须 **0**，否则整轮无效 |
| `truncated_games` | 必须 **0** |
| `decisions_per_game` | 每局决策数（异常升高可能是"越打越犹豫"） |

默认规模：**512 局**（≈11 分钟 / 1 张卡）。要更强的置信区间再加大，但必须报告样本量与置信区间。

> **样本量唯一口径（用户 2026-11-14 定）**：验收一律 **512 局**。
> 历史上用过的 96 局、192 局**正式作废**（样本不足，正是"5.4375 vs 5.299"那类误判的来源）；
> 768 局只作为**赢家场网关**的历史记录保留，不再作为验收门槛。

## 4. 协议对齐（不比协议就不许比分数）

两轮结果只有**同时满足**下面全部条件才可比较：

1. **同一引擎**：`hsbg_engine 37.0.2.256589`，源码指纹 `c4c71014e3d41760`；
2. **同一对手场**：同一份快照库目录（例如 `arena-cal-v3-snap`）+ 同一 `--mirror-sample` / `--mirror-p` / `--mirror-seats`；
3. **同一冻结契约**（唯一真值 `hsbg/az/train/eval_policy.py::TRAINING_CONTRACT`）：
   `max-actions-per-turn 100`、`forbid-unfreeze 1`、`forbid-cancel 1`、
   `move-guard 1`（cap **2** / repeat 2）、`freeze-cap 1`、`ban-trinkets 1`；
4. **同一 seed 集**（默认 `930000`，512 局）；
5. **`protocol_sha256` 一致**。不一致就是**不同榜**，禁止混比；
6. **考试场必须是 held-out**：判"真进步"用的场地**不能是候选训练时用过的战团库**。
   论文的原话是"考试库绝不用于训练；训练用另一批同源战团"。候选在训练场上测出来的优势里
   有**主场优势**，只能叫"主场成绩"，不能据此换冠军。

> **2026-11-14 补的规则 6 是怎么来的**：第一轮训练直接用 `arena-cal-v3-snap` 训练，
> 又在同一个场上评测，得到 `mean_rank 2.615→2.352`、吃鸡率 41.6%→48.6%。这组数**看着很好**，
> 但冠军从没在这个场地上训练过 ⇒ 存在主场优势。于是用 `firestone-bank-6k/eval-m6k.jsonl`
> （与训练池不同的 1,349 局）按**同样的系数**建了 `arena-cal-v3hold-snap` 做交叉验证。
> **凡是有"候选赢"的读数，都要在 held-out 场上复现一次才算数。**

## 5. 判胜规则

2026-11-17 已有用户口径：**不以单一指标判胜，主看逐回合 M1 与增长曲线，名次作参考**。
先检查协议、模型身份、样本和工程有效性，再联合报告逐回合样本量、共同存活子集、
M1/M2、增长曲线和名次配对区间。本文不新增阈值，也不自动换冠军。

以下为**历史 rank-first 规则**，保留用于解释 `tools/compare_panels.py` 当前 verdict 的来源；
其自动 verdict 只能作诊断，不能替代上述最新用户判读口径。是否调整算法阈值仍待用户决定。

```
第 0 步：有效性 —— illegal_actions==0 且 truncated_games==0，否则整轮作废，先修工程
第 1 步：结果刻度 —— mean_rank 是否优于冠军（要求方向为正，且报告置信区间）
第 2 步：过程刻度 —— M1 在 T8/T10/T12/T14 与全程是否不明显退化
第 3 步：结论
   · mean_rank 变好 且 M1 没有明显退化  → 进步，换冠军
   · mean_rank 变好 但 M1 明显退化      → 判定为"可疑进步"（可能只在刷分），必须归因后才能换
   · mean_rank 没变好                   → 不算进步，进入归因
```

**不支持"点估计好一点点就换冠军"**：至少要看置信区间；只有明显超出波动才换。

## 8. 已知陷阱

1. **不要把中位数相加**（见 §2）。
2. **n 会随回合下降**（死人退出样本），T16 以后样本 < 200，波动大，别用小样本下结论。
3. **换协议 = 换榜**：不同 `protocol_sha256` 的数字放同一张表就是错。
4. **过程刻度会被对手场影响**：M1 是"我们的板面"，但对手强度会改变我们能活到几回合、能拿多少资源，所以**比 M1 必须同场**。
5. **训练内遥测（`tel_*`）只有 T6/8/10/12/13 且是均值**，只用于监控，不能代替评测的 M1/M2。
6. **`gap-*` 报告里的 `panel.opponent` 字段是历史遗留的固定字符串**，不要拿它判断用了哪个场地，要看命令里的 `--mirror-snaps`。
