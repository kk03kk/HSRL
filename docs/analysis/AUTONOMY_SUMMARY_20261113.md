## 2. 建成了什么（可复用资产）

### 2.1 运维层：单 Agent 双环境（本地 Windows + NUS 集群 + GitHub 归档）

- `ops/hsai_ops.py` 成为唯一远端入口（`state / probe / push / pull / sh / sbatch / tail / model-pull`），
  带**登录节点守卫**（重任务在登录节点默认被拦）。
- **隧道自愈**：用户登记一次密码（DPAPI 加密）后，VPN 重连后的隧道重建从"卡住十几分钟"变成
  **实测 7 秒**（5 s banner 预检 → 0.07 s 脱离式启动 → 6 s 轮询 → probe），流程写死在
  `docs/nus/TUNNEL_FAST_PATH.md`，Agent 自己调用，不再让用户当中转站。
- **续训守卫**：`personal.py` 用 `training_source_digest()` 拦住"代码变了却冒充精确续训"；
  也因此定下硬规则——**有作业在跑时 digest 相关改动只能进侧分支**（D-037）。
- 三端一致性有自动判据：`state` 报 `IN SYNC`（heads 相等 + 两端 `dirty=0`）。

## 4. 方法论上的最大成果：发现"我们的强"是假象

| 对手场 | mean_rank | 前四率 | 吃鸡率 |
|---|---:|---:|---:|
| 7 个引擎 bot（旧口径） | **1.177**（饱和） | 1.000 | 0.854 |
| **7 席真人战团（新口径）** | **5.4375** | 0.323 | **0.000** |

配合逐回合拆解得到的**悬崖**：活到 T8 0.906 / T10 0.833 / **T12 0.354**，`max_turn_p50 = 11`；
T8 板面 280 **领先**对手 p75 的 241，T10 起 0.44× → 0.23× → 0.15×；同期等级落后整整一档
（T10 4.44 vs 真人 5.52）。

> 结论：瓶颈**不是深的后期**，而是 **T9–T12 的过渡段**；而"每格强度"（T12 170 vs 712、
> T14 268 vs 3891）说明缺的是**乘法引擎/投资**，不是格子数（两边都是 7 格）。

## 5. 被反复验证的六条规律（写进配方约束）

1. **覆盖 ≠ 强度 ≠ 名次**：六个独立臂（H2/H6/H7/H8/H9/H10）都出现"覆盖翻倍、名次中性"。
2. **可被单独满足的过程奖励一定会被打穿**（tier-target 无门控 → 板面 −33%、覆盖 −70%）。
3. **名次奖励饱和时，任何过程奖励都没有纠偏力** → 先把环境（对手）变强，名次才有信息量。
4. **短窗口读数系统性乐观**：G2 在 42 轮"看起来没问题"，208 轮才露退化 ⇒ 必须跑满预算再判。
5. **奖励口径必须指对地方**：`board-target` 用 Σ 总量，而差距在"每格强度" ⇒ 三次证否。
6. **anchor 日程不核对，实验不可归因**（D-039/D-040：整夜 fork 全卡在 0.1，比 champion 紧 5×）。

## 7. 关于群友（第三方）模型的逆向结论

无代码、无权重可用，但**外观审计**给出了三条有价值的配方事实：

（`keep_start_board`）他们把掩码当训练规则用，实测影响 0.10–0.14 名。
另外证明了观测 schema 与我们同源：3227 = 68 + 7×31 + 10×40 + 8×40 + 16×40 + 7×9 + 7×7×31，
两边卡表都是 3983 —— 设计血缘相同，所以"配方"可以学，"权重"不能拿。
