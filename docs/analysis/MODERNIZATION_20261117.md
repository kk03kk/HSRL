### 运营与阵容观察

- **升本节奏基本不变**：两边到 2/3/4/5/6 本的首次回合中位数都是 2/5/6/8/9；6 本到达率均为 500/512（97.66%），T10 平均本数均 5.99。取消教师对 6 本的直接目标没有在本次比较中改变已学到的快速升本倾向。
- **经济使用没有发现大量闲置金币**：按每局阶段内回合均值再跨局平均，前/中/后期剩余金币，旧为 0.2375/0.1140/0.0369，新为 0.2223/0.0864/0.0172。两边 T6 以后均没有结束回合剩余 ≥3 金的记录；这不证明购买或刷新选择最优。
- **后期动作更多**：T12 新模型购买 4.03、刷新 5.33、打出 7.98 次/回合；旧为 3.77、5.13、7.68。两边 T12 都每回合移动 2 次、冻结 1 次，恰好到契约上限。这提示固定习惯仍在，单凭频数不能判断每次移动/冻结都无效。
- **阵容结构没有明显跃迁**：T12 金卡均数 1.00 → 0.97，有金卡比例 61.4% → 59.4%；平均每格攻击 111.7 → 116.1、生命 95.1 → 96.7。全局磁力动作 2,282 → 2,890，可能与构筑选择或存活长度有关，不能仅凭总次数归因。
- T6 以后结束时手牌 ≥3 的回合数 207/3,776 → 241/3,881；两边强制结束回合记录均 0。手牌留存需结合卡牌、场面、合法动作及未来价值逐例审阅，不能直接贴“错误决策”标签。
- 按 seed 顺序选取前两个 T12 共同存活且新模型手牌 ≥3 的例子（930002、930006），已抽出双方完整动作。新模型都是满场 7 个随从、0 金、主动结束；手中分别留 3/4 个随从，不能直接打出，需要先卖场上单位。这个例子不支持“有合法免费打出却没打”的简单结论。
- **可复查的冗余移动**：seed 930006、T12，新模型全局动作序号 137/138（0 起计）连续执行 `243 = Move { from: 6, to: 5 }`。第二次将相邻单位换回原位；到动作 139 前，记录中的板面完整对象、手牌、金币、本数、血量与第一次移动前一致。它消耗两次动作额度而没有保留阵容排序改变。是否扩展防往返规则涉及冻结动作契约，故仅记录建议，未修改策略或规则。原始例子在服务器 `artifacts/runs/nus-decision-examples-v14-r1-20261117-1/`，本地有经 SHA 校验的 `decision-summary.json`。
- 快照注入为旧 45,409/45,415、新 45,444/45,449；分别有 6 和 5 次 missing/fallback，错误均 0。按既有 strict=0 协议合格，**不是 100% 注入**；没有为了追求全满另换规则。

## 已知限制与保留风险

1. 完整逐动作记录覆盖学习模型实际执行的动作。原生 bot_play 内部动作没有 API 逐步暴露；对手快照输入由协议、库内容哈希和前后状态约束，不能声称记录了所有 bot 内部决策。
2. 固定 batch 的精确恢复不等于整个分布式采集轨迹逐位恢复。当前 Trainer 保存 RNG、Adam、调度器与 anchor，但未证明所有 worker 和在途 pipeline 状态可完整恢复。原始 Trainer 也没有独立源码 digest；外围工作流守卫与原始 Trainer 不能混为一谈。
3. 发布目录固定源码，环境与资产依然依赖操作纪律和身份校验；不是文件系统强制只读沙箱。NUS 引擎采用原已验证安装，运行期间不得原地重编译或升级依赖。升级使用新环境、新发布。
4. Windows 沿用 NumPy 2.4.0 以保持原本地数值版本；该版本在包索引被撤回。当前测试未复现相关问题，后续版本升级仍需数值/实机回归，不能把版本锁等同于安全漏洞审计。
5. 第三方参考源码的确切原始 revision 和授权范围仍待确认，因此仅保存在受控资产目录，不用于本次正式比较、不发布到 Git。
