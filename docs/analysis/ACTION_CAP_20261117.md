# 动作上限要不要提高？—— 触发率实测（2026-11-17）

状态：**分析记录**。数据源：`artifacts/runs/gap-v1.2-plus3-1024-20261117/panel.json`（r3，1032 局）
与 `artifacts/runs/nus-arena-v1.3-r{1,2,3}/train/history.jsonl`（3 轮共 2,062 轮迭代）。

## 1. 结论

**`max_actions_per_turn = 80` 不需要提高。** 它几乎从不触发：

| 位置 | 触发率 |
|---|---|
| **评测**（r3，1032 局 = 13,031 个回合实例） | **3 个回合**达到 80（**0.023%**）；**3 局**（占 0.29%）出现过 |
| **训练**（3 轮 = 209,834,884 决策 / 1,055,744 局 ≈ 1,340 万回合） | `forced_end_turns` 合计 **1,967** ⇒ **每百万决策 9.4 次**、≈**0.015% 的回合** |

尾部也很薄：评测逐回合动作数 **p50=12 / p90=34 / p99=52 / p99.9=67 / max=81 / 均值 16.4**。
（`actions=81` 表示 80 个真实动作 + 1 次被强制的 EndTurn ⇒ 那一回合确实撞到上限。）

## 3. 真正"天天撞天花板"的不是 80，而是另外两个 cap

| 上限 | 实测饱和情况 | 性质 |
|---|---|---|
| **`move_cap = 5`**（每回合换位次数） | 训练 3 轮累计：实际换位 28,375,061 次；被 cap 掩掉的合法动作位 **26.8 亿个** ⇒ 平均**每个决策 12.8 个动作位**被掩（49 个里约 26%）。评测 T12：move 均值 **5.02 次/回合、使用率 100%** ⇒ **每回合都打满** | **真饱和** |
| **`freeze_cap = 2`**（每回合按 Freeze） | 评测 T8–T12：使用率 **0.99**、均值 **1.55–1.91 次/回合**（cap=2）⇒ 基本每回合打满 | **真饱和** |
| `max_actions_per_turn = 80` | 0.023% 的回合 | 基本不触发 |

## 4. 建议

1. **不要把 80 提高。** 提到 100/120 只会影响 0.02% 的回合，收益不可测；而且它是
   `docs/TRAINING_RECIPE.md` §2.7 的**冻结契约**之一（训练与评测共用），改了会让所有历史面板
   变成"不同协议"，必须整轮重测。
2. **要动就动 move/freeze 这两个 cap，且方向应该是"收紧"而不是"放宽"**：
   它们本来就是防"空转"的去抖约束，而策略现在每回合都撞满 ⇒ 说明存在
   "反复搬随从 / 反复冻店"的退化偏好。放宽只会放大空转（多出来的动作不产生任何战力）。
   便宜的 A/B：`move_cap 5→3`、`freeze_cap 2→1`，看 T12 的 `refresh/buy` 与 M1 是否改善。
3. **如果目标是"让它买得更多"**，那要看的是金币分配（T12：refresh 5.4 次 vs buy 3.8 次），
   不是动作预算——它的回合长度均值只有 31，离 80 很远。
