# 训练对手设计研究：静态快照场为什么给不出中后期信号

状态：**研究说明（只读分析，未改代码、未跑训练/评测）**。
日期：2026-11-17。适用：`deploy/slurm/stage_arena.sbatch` 现行配方（PPO 单学习席 + 7 席严格 EOT 快照）。
口径：主指标 = M1 逐回合中位战力（`docs/EVAL_PROTOCOL.md` §2）；名次面板只作参考。

入口：`hsbg/az/train/mirror_snapshots.py`、`hsbg/az/train/parallel_collect.py`、
`engine/crates/hsbg-engine/src/snapshot.rs`、`tools/build_arena_library.py`。

> **本文不提出"应该把场地设成多少"的最终结论** —— 场地强度属训练策略，由用户决定。
> 本文只回答三件事：为什么现在没有信号、有哪些可选方案、哪个实验最便宜且最有信息量。

---

## 0. 结论先行

1. **现在这个场不是"不够难"，而是"难度不可观测"。** 训练场 `arena-cal-v14` 的绝对目标是
   T12 = 3000 / T14 = 6000 / T16 = 8000 / T18 = 10000（`summary.json`），而同一模型
   （`arena_v13_free`）实测 M1 是 T12 **1266** / T14 **2272** / T16 **3676** ⇒
   **靶是模型的 2.2–2.6 倍**。战斗结果是板面比的阶跃函数，比值 0.4 与 0.7 都表现为
   "整队被清空"，边际为零。
2. **`--mirror-sample` 对难度没有裁量权。** v14 的 T12 桶里 560 帧全部落在
   `[2700, 3300]`，`p50band` 只在这 560 帧的 45–55 分位里取（≈58 帧），可调范围 ≈ ±3%。
   **改采样模式不可能把对手拉进可达区，只有重建库能。**
3. **注入的席位不出手**（`commit_snapshot` 里 `ended_turn = true`），整局 7 席的动作流是空的；
   且注入实体 `pool_copies = 0`，**没人跟学习席抢共享池**。这两件事一起把"中后期运营"
   从环境里删掉了——不是学不会，是环境里没有这件事。
4. **最便宜的判据是一个 10 分钟门禁**：在当前训练场测 `R²(板面→名次)`（D-052 已把它写成
   强制门禁）。它能直接回答"这个场有没有可学梯度"。
5. **自博弈/联赛不建议先做**：算力 6–8×，且单切片下独立局数会掉到 ~1.9 万。

## 1. 为什么静态快照场会导致训练信号不足

### 1.1 奖励饱和：两端都待过 [证据]
- 高压场名次贴随机：1028 局 mean rank **4.55**、前四 **46.7%**（随机期望 4.5 / 50%）。
- 弱场名次贴顶：D-036 实测 7 个引擎 bot 下 `mean_rank 1.177 / win 0.854`，"名次奖励饱和"。
- ⇒ 可学区间只剩"活到第几回合"，这与 D-052 的归因一致。

### 1.2 对手不可响应 [证据]
`mirror_snapshots.py`：「被注入的座位在引擎里 `ended_turn=true`，本回合不再行动」；
引擎侧落在 `snapshot.rs` 的 `commit_snapshot`。训练侧 7 席全注入（`--mirror-seats 7 --mirror-p 1`）。
**后果**：学习席的动作只通过"自己活多久"和"一场比值≈0.4 的战斗"影响奖励；对手侧
"买什么/何时升本/养谁/抢哪张牌"这 7 个自由度全部消失。

### 1.3 名次与板面脱耦 [证据]
D-052：控制死亡回合后，名次 ~ T8/T9/T10 板面的 **R² = 0.000 / 0.000 / 0.004**；
名次 ~ 死亡回合 **R² = 0.65**。`tools/measure_reward_signal.py` 在三个模型上实测
R² = **0.005 / 0.003 / 0.009**（阈值 0.05，全部 FAIL）。
旁证：某轮 iter 139 上 `arena_own_late=1585`、`arena_opp_late=6624`（**4.2×** 劣势），
而 `arena_late_win=0.459` —— 板面差 4 倍、胜率仍报 46%。

### 1.4 难度是"点质量"，而且还是 2× 以上的点 [证据 + 计算]
| 回合 | 桶 n | 强度带 | 实测 p10/p50/p90 | 源回合范围 |
|---|---:|---|---|---|
| 10 | 643 | 810–990 | 827 / 900 / 970 | 6..16 |
| 11 | 610 | 1440–1760 | 1470 / 1588 / 1718 | 5..17 |
| **12** | **560** | **2700–3300** | **2759 / 3000 / 3234** | **7..17** |
| 14 | 554 | 5400–6600 | 5501 / 5965 / 6478 | 9..17 |
| **16** | 498 | 7200–8800 | 7317 / 7928 / 8577 | 8..17 |
| 18 | 457 | 9000–11000 | 9249 / 9933 / 10784 | 7..17 |

`abs_targets` = 3000/6000/8000/10000，且 `tools/build_arena_library.py` 里 **`--targets`
覆盖 `mult`** ⇒ 库里的 `mult`（0.82/1.16/1.22）是**死字段**，靶与"模型的 1.15×"彻底脱钩。

### 1.5 三重分布外：不消耗动作 / 不占池 / tier 不自洽 [证据 + 推断]
1. **动作流为零**：7 席全注入 ⇒ 对手侧动作数 0（历史对照：同网络 8 席时对手动作 1,566、
   引擎 bot 时 971，见 `docs/analysis/TRACE_UNIFIED_20261111.md`）。
2. **不占共享池**：注入实体一律 `pool_copies = 0`。8 人局里最稀缺的资源（tier5/6 每卡
   仅 7/5 份）实际变成学习席独占 ⇒ 抢牌、卡等级、池位枯竭这些机制在训练分布里不存在。
3. **tier/饰品不自洽**：帧由一局 **turn-2 模板 game** 构造，`commit_snapshot` 只替换
   `tier/gold/shop/board/hand/hand_queue`，而 `trinkets/quests/effects/counters` 保留当前局
   原值 ⇒ 一个 T12 对手可能带着 T5 的 tier、T2 模板的商店、本局随机发的饰品，却挂着
   T17 强度的板子。

### 1.6 `p50band` 的多样性上限 ≈ 每回合 58 个对手 [证据 + 计算]
单座位库允许跨座位回落到唯一 seat ⇒ 7 席共用同一桶；`p50band` 取 45–55 分位 ⇒ n=560 时
只有 58 帧（强度跨度 ±3%）。7 席有放回抽样，**约三分之一的回合里桌上至少两个对手是同一块板子**。

### 1.7 跨回合借用 ⇒ "等级—强度"关系统计上被污染 [推断]
`pick_boards` 明确「只看强度，不看回合」，T12 的帧来自 T7–T17。学习席从对手身上能读到的
"等级→强度"关系因此不可信，而这正是本项目最需要它学的量。

### 1.8 两条注入路径能力已分叉 [证据]
| 路径 | 待选结算 | 落地率 |
|---|---|---|
| 镜像快照（现状） | 有（`_resolve_pending_for` 先结算 `pending_choice`） | **99.98%** |
| 人类战团（`--human-board-*`） | **无** | **52.8%**（9,162 次拒绝**全部**是 `pending_choice(1)`） |

⇒ 任何"用人类战团做行动型对手"的方案，先要修这一半的注入失败。

### 1.9 闭环难度控制器存在、跑过、并且失败了 [证据]
`opponent_arena.py` 在 11-14 的 A/B 臂上跑了 140 轮：把 late 顶到 **4128**（自身 1585–2503），
并在"mid/late 胜率达标"时**触发棘轮**收紧目标。真实原因是两条测量缺陷叠加：
47% 座位注入被拒退回弱 bot（§1.8）+ 胜率只在"活到该 band 的局"上统计（存活偏差）。

### 1.10 统一机制（一句话）
> 学习席的动作 → 奖励，只有两条通道：**活多久**，和**一场比值≈0.4 的战斗**。
> 前者在胜率 0.46–0.49 下已饱和，后者处在阶跃函数的平坦段。对手侧的 7 个自由度被
> `ended_turn=true` 关掉了。所以"中后期运营"在这个环境里既不可教、也不可罚。

## 2. 方案对比

| 方案 | 实现成本（可复用度） | 3 小时能跑多少 | 中后期运营信号 | 主要风险 | 与现有基建 |
|---|---|---|---|---|---|
| **A 静态校准快照（现状）** | 0（已上线） | 3.0–3.3e7 决策 | **无** | 与真实局系统性错位（不抢池、tier 不自洽、难度点质量） | 原生 |
| **B 引擎 bot 混编** | 极低（`--mirror-seats k` / `--mirror-p<1`） | ≈A | **仅早期**（bot 会升本/买牌，但不会滚雪球） | 难度骤降 ⇒ 名次饱和；混编让"真变强 vs 对手变弱"无法归因 | 原生 |
| **C 自博弈（8 席共享权重）** | **高**（300–600 行：PPO 无多席记录、`PPOSelfPlayPolicy` 无 `act_batch`、`BatchEnv` 无注入钩子） | 样本 ≈3e7，但**独立局 ÷8 ≈1.9 万** | **最强**（比值恒≈1） | 8 席同策略 ⇒ 对手多样性=0，可稳定过拟合自己的漏洞；无人类锚 | 低（与注入互斥） |
| **D 历史快照联赛** | 中：策略形态已有 `--frozen-seats/--frozen-opponent`（单 ckpt、座位 1..N）；**快照形态 0 行**（`league-src-*` 就是模型自己的 EOT 帧库） | 快照 ≈A；策略形态 1/6–1/10（7 席串行单样本前向） | 快照：只加形状多样性；策略：**有行动**，上限=历史最强代 | 样本效率最差；冻结代过强 ⇒ 回到不可达区；`_OPP_CACHE` 无上限 | 快照完全兼容 |
| **E 混合（低回合 bot / 高回合静态靶）** | 低（缺一个 `mirror_min_turn`，~10 行） | ≈A | 前半段有、后半段仍无 | 两段拼接处不连续；human-board 路径 53% 注入失败会静默退化 | 中 |
| **F 教师蒸馏（不动对手）** | 低（全部现成、全关着） | ≈A | **直接给"该怎么做"**，但教不了"被压制下的取舍" | 分布错配已证；过程奖励叠在饱和主奖励上无效（D-036） | 完全兼容 |
| **G 行动 bot + 采集后校准** | 小（语义已实现，collect 侧未透传） | ≈A | 只体现在池竞争/经济压力 | **已被实测否决一次**：`end_turn=False` 会让实战场系统性高于标称 | 中 |

## 3. 推荐：最小可验证实验

### 3.0 先跑 10 分钟门禁（判据，不是新实验）
用当前模型在当前训练场跑 512 局面板（实测 295 s）→ `tools/measure_reward_signal.py`。
- 预期：signal R² ≈ 0.00x（与 D-052 同量级）⇒ 确认"这个场没有信号"。
- 若意外 ≥0.05：本说明第 1 节需要重写，先别做 P1。

### 3.1 P1（首选，3 h，单切片）：**只把 T12+ 的靶拉回 ×1.15**
- **假设 H1（可伪证）**：T12–T16 的 M1 停滞由"靶 2.2–2.6× ⇒ 比值进入阶跃平坦段"造成。
- **干预变量（唯一）**：训练场 **T12–T20 的目标强度**；T1–T11 逐位不变。
  参考值（用 `arena_v13_free` 面板 ×1.15，T17+ 线性外推）：
  T12 **1456** / T13 1968 / T14 **2613** / T15 3386 / T16 **4227** / T17 4900 / T18 5800。
- **其余全部冻结**：同 sbatch、同 seed、同 `p50band`、同奖励表、同教师计划。
- **前置**：重建库（**CPU 作业，不占 GPU**）；然后在 v15 场跑一次 512 局 + `R²` 门禁。
- **成功判据**：固定考试场（同 seed、512 局）T12–T16 的 M1 中位 **≥ +10%**，配对 95% CI 不跨 0，
  且 T6–T9 退化 ≤5%。
- **失败判据**：T12–T16 平/降 ⇒ 结论是"不是难度问题"，这时才值得付 C/D 的算力。
- **工程红线**：`illegal>0`、`truncated>0`、注入率 <99.9%、非有限损失（现在由
  `hsbg/az/train/health_gate.py` 自动拦）。

### 3.2 P2（仅当 P1 失败）：会行动的对手性价比探针
`--frozen-seats 7 --frozen-opponent <冠军> --mirror-p 0 --mirror-seats 0`，
只量三个数：decisions/s（基线 2,826–3,028）、工程洁净度、M1 是否崩。
成功（吞吐 ≥25%、M1 退化 ≤10%）才谈联赛；否则记为"单切片算力下不可行"。

### 3.3 如果 P1 成功：把"按轮重建"当成能力匹配
每轮结束 → 512 局面板（+5 min GPU）→ 用新 M1 重算 T12+ 目标（×1.15~1.3）→ 重建库
（+20 min CPU）→ 下一轮用新库。每轮 25 min，比值被钉住，也不需要修闭环的两条测量缺陷。

## 4. 不建议现在做

| # | 不做 | 理由 |
|---|---|---|
| 1 | C 全自博弈 | 改造量大 + 8 倍前向 + 对手多样性=0；用 D 的快照形态能以 0 行代码拿到 80% 的信息 |
| 2 | 重跑 `--arena-config` 闭环 | 已跑 140 轮并失败，根因（53% 注入被拒 + 存活偏差）未修 |
| 3 | 把 B 单独当实验臂 | bot 后期板面≈0 ⇒ 混编让 M1 上升无法归因 |
| 4 | 打开 `end_turn=False` 提信号 | 已实测"难度闭环被顶穿"，要用必须先重标定靶（= 两个变量） |
| 5 | 重开过程奖励 | D-036 已在饱和主奖励上验过一次（T12 −33%）；先修对手 |
| 6 | 单纯加算力/加长同配方 | R² 与训练时长无关；加卡会同时放大"错场"的代价 |
| 7 | 用教师替代对手 | 给不了"被压制下的取舍"；建议作为 P1 成功后的**第二变量**单独一轮 |

## 5. 待确认

1. 用户口径的"对手是模型的 1.5–2.2 倍"与本文按 `arena_v13_free` 算的 1.63–2.64× 不完全一致；
   差异可能来自对比的面板/回合。**建议以后同一张表里同时给 M1 与靶**，否则比值不可比。
2. T17–T20 的 M1 样本量（n=53/24）太小，那一档的比值只作参考。
3. P2 的吞吐是估算（7 次串行单样本前向），必须用 10 min smoke 定案。
