## 本地复现结果

- 作者 3 项测试通过，覆盖实际检查点加载、字节与 Base64、单步与批量选择一致、1 局完整对局。补丁自带 6 项观测测试通过，覆盖基础观测前缀、对手隐区和选英雄信息隔离等。
- 另跑的 8 局全部第一，前四 8/8，平均名次 1.00。2,847 次决策中有 269 次购买、940 次出手牌、560 次 `Choose` 类编号、54 次 `Magnetize` 编号区间动作。选英雄、发现与选择目标可复用选择编号，不能从编号统计直接推断 560 次发现。0 次非法返回，0 次中断。
- 首两步去除后的 2,831 次单决策推理 P50 6.71 ms、P95 9.49 ms。计时含解码和推理，排除模拟器观测生成、真实抓取、输入和服务器回执。
- 人工把掩码仅开放原生 Move 244 后，作者封装切掉该位置，返回被禁用的 0。集成层需在推理前拒绝空交集，并再次核对输出仍属同一帧合法动作。
- 可微路径实验复用了作者网络组件，在同一观测上按两阶段概率计算策略项及价值项。词嵌入、循环单元、价值头分别得到有限非零梯度，范数为 0.00448、0.03481、0.11419。没有做优化器更新。

复现实验在 `artifacts/runs/local-asd-checkpoint-audit-20261121-01/`。`audit_smoke.py`、`audit_parity.py` 与 `smoke-result.json`、`compat-result.json` 分别记录运行方法和结果。`author-tests.log`、`visibility-tests.log` 为测试输出。

## 同版本评测如何落地

两份原生扩展逐行比较，3,983 个真实卡牌 ID 的顺序完全一致，另有索引 0 表示空项。245 个动作逐号名称均一致。作者策略只拥有前 196 个动作，入场落点仍可选，已在场随从的 49 个 Move 动作不可用。HSAI 当前训练和实机的 150 步、三次场上换位、冻结和解冻合计两次规则与作者演示的 100 步、直接读原生掩码不同。

两份卡数据有 160 条记录变动，其中 120 行原生静态卡张量值不同。作者模型在构造时调用 `card_static()`，其张量不随 checkpoint 保存。即使严格加载权重成功，接错静态表也会改变模型输入。比如 `BG23_017` 的血宝石全局增益从 +2/+1 变为 +1/+1，`BG27_016` 的基础攻血和增益从 8 变为 12。比较时应记录对局规则版本与模型使用的静态表版本。第一轮以原表复现发布策略，当前静态表可单独作为配对消融。

推荐在隔离的当前引擎提供 `observe2` 和逐座位状态适配器。先验证同一状态的基础前缀、块顺序、归一化、卡位和掩码，再在同一批种子、换席和对手库下比较 0750、R1、3286。先设共享 196 动作与相同回合预算，隔离换位权限的影响。随后单独报告各模型原生动作权限下的表现和差值。名次、前四、冠军、配对名次和逐回合模型强度都应记录。分析阵容时同时记录固定回合的成型率、成型后强度和样本量，以减少终局幸存者偏差。这些结果使用独立协议。8 次战胜作者原生 bot 只说明基准跑通，并提供该样本下的结果。

## 实机接入的阻碍

现有实机入口 `client/hsrl_agent/live/policy.py` 验证当前权重的 Player150 契约。Player150 是 4,967 浮点数、124 卡位、245 动作。0750 是 4,017 浮点数、447 卡位、196 动作，而且含循环状态。已有针对其他群友模型的 `thirdparty:` 入口使用另一种 checkpoint 和模型 API。

| 数据 | 当前判断 |
| --- | --- |
| 自己的英雄、棋盘、手牌、商店、发现、金币、酒馆等级 | 现有实机解析链可复用。实际槽位和当时的服务器选项仍需逐帧核对。 |
| 附着牌 ID 与次数、临时攻血、专项成长、英雄技能内部数值、队列、定时效果与精确脚本计数 | `observe2` 直接读取模拟器内部结构。部分可从已公开标签、提示或当时事件重建。逐字段覆盖率、等价性和可见时机待确认。 |
| 见过的对手战团及附着物 | 默认 `sees_all_boards=false`，从当前玩家自己的上次交战记录读取。全战团诊断路径可绕过该限制，评测和接入应显式关掉。发布原训练是否开过该旗标待确认。 |
| 对手榜单族数、走势、饰品和技能、已宣布的下家 | 源码把它们当公开信息。客户端实际公开的字段及出现时机要逐项验证。不能把当前回合对手私有战团或事后事件回写给旧决策。 |

接入前应先以历史日志做只推理回放。专门覆盖 7–10 张手牌、目标类动作及发现。掩码取实时客户端许可、现有绑定与安全限制、模型动作支持范围的交集。循环状态按局、按座位维护，只在该决策得到有效提交回执后确认推进。相同观测重复轮询、点击失败或 UI 自动恢复不重复推进。断线后只有完整可信的已提交历史才能重建原状态，否则显式等待或使用经过测试的恢复方式。对缺失观测做按块消融，测合法性、动作分布偏差和棋力，再决定是否进入实机验证。

## 两种分叉学习方案

1. **保留 0750 架构。** 从公开 Actor 和 Value 初始化，建立新的优化器、采样合同和环境版本。其策略先选源动作组、再选该组的目标。PPO 的动作概率要计算两项之和，并按每局连续轨迹重放循环状态。显式记录暂停、批内席位切换、终局和强制动作的边界。作者的 `step` 与 `act_batch` 均为无梯度接口，正式训练需使用可微组件并验证更新前概率重算一致。若未来要增加 Move，新增动作能力作为单独实验验证。
2. **冻结 0750，蒸馏到标准 Player150。** 先用配对评测识别它明显更强的卡组或局面，再在同一局面绑定教师的序列历史与学生可见的非特权观测。教师无法迁移的字段需做遮蔽对照，避免学生学习依赖隐藏前提。学生使用自己的动作能力和实机契约，后续可按现有 HSAI 流程微调。

现阶段优先做同版配对评测。若实际目标是实机吸收可迁移策略，且原观测可见性不达标，优先考虑方案 2。若目标是研究 `observe2` 与时序记忆的增益，方案 1 更直接。
