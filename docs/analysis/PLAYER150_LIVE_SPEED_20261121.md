# Player150 实机操作时序审计

2026-11-21 · 模型 3286 · Windows 炉石构建 255790

## 准入和恢复

实际鼠标输入之前核对连接、完整新日志、服务端 Options 或本方 EntityChoices、实体身份、窗口和目标几何。先保存持久账本，再发送输入。按下前被拒绝时撤销本地意图。已按下但送达未知时保持账本，等客户端提交和服务端结算证据。

| 动作 | 可尽早执行的证据 |
| --- | --- |
| 普通三选一 | 本方同一个选择请求，两帧均识别完整卡槽，点击点处在选中卡的两个实测框内侧。允许无关卡牌和卡面动画继续。鼠标按下前再核对命中和授权。英雄、饰品和宽布局沿用各自证明。 |
| 出牌 | 保留手牌源实体和槽序、落点、必要邻位。无目标法术使用容器落点，不等无关随从特效。7–10 张手牌沿用上缘抓取。 |
| 买牌 | 保留店铺源和本次拖放起点、落点。少于 7 张手牌时去除远处手牌动画依赖。买入后按新手牌授权决定何时能打出该实体。 |
| 出售、换位、磁力 | 出售不等无关手牌动画。换位保留顺序、源、落点及邻位。磁力保留合法目标和位置。 |
| 刷新、升本、英雄技能、冻结、发动 | 用户可见的当前按钮、真实授权及相应区域的局部证据。技能含目标或分支时按阶段验证。冻结的旧按钮防抖保护保留。 |
| 分支、确认、结束回合 | 按实体和事务阶段核实。结束回合沿用 Player150 的停手语义。 |

快速时序把试验拖动路径从 96 ms 降到 72 ms，松键后停放等待从 120 ms 降到 80 ms。在等回执的循环把指针移至右下角，遇焦点变化、手动按键或停放点遮挡时保留输入门禁。已证实无客户端提交时，相应手势类别退到原先实测时序，下一次以重新读取的状态决策。

## T6 整轮停手

首局 Power.log 第 49,093 行的可执行快照中，无畏的食客 `BG30_123`（手牌实体 2419）同时有 `POWER option 1`，其分支为 2420、2421，以及同源、无目标的普通 `POWER option 2`。两者投影到相同的三个落点 46、47、48。旧桥接因重复授权含义不同拒绝整个动作表。

当已知手牌带 `CHOOSE_ONE=1`，同一实体、落点及无目标普通行与明确分支行同时出现时，保留列出分支实体的授权。其他无法证明等价的 Player150 槽位单独屏蔽。原始帧重放返回 22 个动作，46–48 均保留 Option 1 和两个分支。正反输入顺序及未知冲突都有回归。

试验二最高记录为 T6 的 31 次确认，首个决策到最后一笔回执跨度 79.1 秒。原始日志归档和追踪写入完整，全部操作动作中 3 笔分支出牌没有对应的模型分支选择。客户端提交和服务器结果可见，不能归功于模型。试验一有一次买牌拖放没有向客户端提交，原状态重新决策后买入成功；验证以实际客户端提交和服务器结果为准。现阶段缺少后期 150 步验证，也没有端到端十倍提速的证据。

## 停机后的离线修复

旧版延迟回执检查在等待中把仅含 client 字段的状态交给动作映射，导致 `KeyError('view')`。普通单阶段事务现在先核对原始提交，再在可投影状态下重绑。必须匹配玩家、选项、源、目标或位置，并看到比客户端提交更新的 Options 仍列出完全相同的授权才能归档为拒绝。含分支的事务继续依靠其结算链，单凭沉默和局部画面不能重发。三个真日志回放在提交行均保持等待，在真实结算行均以外部完成归档，不计模型成功。

对分支出牌的首次拖动恢复已实测的原先输入节拍。运动区域的差分只计算一次，反复捕获期间合并同类等待状态的写盘。普通快速发现按下前再读取一次授权。上述停机后的改动使用离线回归，未开启新对局。

曾调查是否可通过客户端逐实体日志跳过尚在播放的动画。173 个历史出牌、换位、卖牌和买牌决策中，即使到了已派发状态，手牌或棋盘对象投影仍有 5 帧与可执行状态不完全相同。该投影暂时只作诊断，整条播放门禁保留。快速时序 `--timing rapid` 仍是显式试验模式，控制台继续使用 `fast`。两种模式共用日志缓存、回执修复、指针服务和动作映射修复。

最终专项回归 122 项通过、5 项因工作树缺少旧归档而跳过。没有重新开启实机，模型和服务器训练未改。
