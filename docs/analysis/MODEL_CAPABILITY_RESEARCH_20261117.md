# v1.4-r1 模型能力与下一轮强化学习研究

状态：研究报告；分析现有证据，不授权新训练或科学设计变更。日期：2026-11-17。

## 结论与证据等级

最值得推进的路线是：**先补足可见机制状态，再用经过原生模拟器验证的多步经济循环示范建立能力，最后用分阶段 PPO 把这些技能接回整局。** 不建议原样再堆一轮长训，也不建议首先加大奖励、提前强制六本或直接扩大 Transformer。

当前模型不是“完全没学会”，也不是“六本升不上去”。它已学会一批真正有效的圣盾、龙、机械和自动成长协同；正式评测中 500/512 局到过六本，首次六本的回合中位数为 T9。但高经济组件的选择、组装、循环兑现极少，常见路径仍是把正常金币预算花完，再依赖现有场面自动成长。

本报告区分三类结论：

- **直接证据**：训练账本、完整正式轨迹、当前源码、确定性 CPU 状态对照。
- **有支持的解释**：欠缺循环示范、保守路径自我强化、对手压力压缩投资窗口；尚不能量化各自贡献。
- **待验证的方案**：输入扩展、机制课程、搜索蒸馏、分级对手、信用分配等；没有实施，也没有宣称已证明有效。

最硬的新增发现是**观测混叠**：罗杰斯的奖励进度不同，模型看到的 3227 floats、124 cards 和合法动作可以完全相同，而下一次花金币产生不同收益。扩大同一种无记忆网络、继续采样，并不能恢复被输入丢弃的信息。但这个缺陷也不能独自解释所有差距：模型对铜须等组件的低采用率，仍需用探索和训练分布的实验证据解释。

## 2. 两份参考资料的身份

### 2.1 AutoTavern

本地原文：`records/source-docs/papers/autotavern.pdf`，20 页，SHA256 `1dbebcb9cb67aba30bb0328b98fd6b7a19a6811880cfd7f64c8babea89583c89`。核对了正文 §6、附录 C/F，渲染检查 PDF 第 14–15 页的 Table 7/8、Figure 6 和相关说明。

论文是 [Build, Don't Play，arXiv:2610.33845v1](https://arxiv.org/html/2610.33845v1)，提交日期 2026-10-24。官方仓库明确：公开 TavernGym/TavernBench，**未公开 TavernAgent 权重、训练代码和题目生成器**；当前模拟器为 37.0.2，论文基准保留 36.6.3。不能把当前 HSAI 与论文曲线当成同版本、同考试的分数比较。[作者仓库说明](https://github.com/MCG-NJU/AutoTavern#overview)

论文给出的有效线索：

1. PPO 本身足以达到很强能力，但它依赖环境、输入、训练分布和持续迭代，不是照抄几个超参就能复现。
2. 后期 stage 约 300 轮、每轮 1.05M 决策，约 310M 决策/570k 局；从前一 stage 接续，前 100 轮有 KL anchor。Table 7 的 `512 × 256` 是采样配置，不能解释为“每回合允许 256 动作”。
3. 早期网络规模实验每个模型是 400×约 4.2M，即约 **1.68B** 决策。其“大模型只短训一会儿”的直觉不成立。
4. 23 个发布版本并非 23 次相同超参训练：包含规则扩展、玩家视角、目标调整、对手重新校准、分级库、专长模型合并和环境修正。`23×310M≈7.13B` 只能作预算量级示意，**不是论文披露的精确主线总样本数**。
5. 论文附录 F 报告主线约 1,900 GPU-hours，其他探索/消融/放弃分支约 16,700 GPU-hours，评测分析约 1,300 GPU-hours；配置为 8×H200/128 CPU。不能把这些等同于我们的 H100 MIG 运行小时。
6. 最有因果支持的是对手校准消融：同起点、同 150 轮预算，主考试夺冠率 20.9%→27.2%，更难考试 10.3%→13.5%。校准的是**学习者实际遇到的对手**，包含手牌、隐藏计数和高上限/烈毒等机制分布，不只是把攻血 P50 往上调。
7. Figure 6 自己注明是幸存者成长曲线，库对手也不是人类同桌。论文中后期巨大身材值得研究，但不是与本项目 M1 的直接胜负证明；图中也未给出本项目采用的 P50 计算口径和原始样本。

## 3. 历史到底训练了多少

### 3.1 三本账必须分开

CPU 盘点遍历现存历史 JSONL，以规范化完整记录 SHA 去重副本；不加载历史模型，不重新研究旧库。139 份服务器 history 文件中 127 份包含训练行，12 份只有启动头；解析错误 0。副本、分叉、失败后重采样和优化器未消费样本分别登记。

| 口径 | 结果 | 限制 |
|---|---:|---|
| 服务器所有 history 的原始决策计数直接相加 | 3,835,379,254 | **含副本，不能当总训练量** |
| 完整行去重后的服务器采样 | **3,374,640,638** | 32,273 条不同训练行，15,272,220 局；含 smoke、弃用分支和重采样 |
| 本地独有 CPU smoke | 3,393 | 大历史与服务器 SHA 相同，不能再加一遍 |
| 两端可核实的去重历史采样 | **3,374,644,031** | 这是可见记录口径，不等于现役模型继承量 |
| 早期缺原始日志的前缀 | 账面反推 **198,819,917** | 依赖 V1.1 累计 manifest 与所选版本边界；不是重新逐步验证过的原始采样 |
| 若将该前缀计入项目累计 | 约 **3,573,463,948** | **推算值**，不宣称项目终生精确总量已穷尽 |

服务器去重采样按路径族分解：早期三条长训 913,989,817；league 763,330,056；entry 试验臂 615,206,809；arena 家族 1,060,597,473；其他探针等 21,516,483。它们包含互相放弃的分支，不能顺次接到一个模型上。

当前权重谱系按来源指针为：league-final → v3 → v5 → v6 → v7 → v8 → v11 → v12 → v13（别名 v1.2）→ v1.3-r1 → r2 → r3 → v1.4-r1。**v9 三轮没有进入当前谱系。**

- league-final manifest 累计 1,552,463,499；其 history 的 5,315 行只对应 5,167 个不同累计 update。按每个 update 最后保留记录重算，增量 741,961,671，恰好等于 `1,552,463,499−810,501,828`。恢复/重试确实使“日志全加起来”与最终权重继承量不同。
- 之后上述 12 个 arena 段共采样 **827,575,870**，记录的 `processed_samples` 共 **808,261,969**；差额 19,313,901 不能冒充完成了优化。processed 是样本消费计数，不是梯度步数，也不保证样本内容互异。
- 因而按冠军累计值加后续分支预算，现役链的**采样账面约 2,380,039,369**。其中包含未完成 PPO 消费的采样；早期实际消费总量无法从现有记录完全还原。
- D-065 把 v9 三轮写成约 5,400 轮/600M，实际是 **1,675 轮/210,690,977 决策**。本报告纠正口径，历史决策原文不改写。

### 3.2 最近一轮的有效学习量

v1.4-r1：745 轮、381,440 局、69,691,656 决策；全部 69,691,656 都进入 `processed_samples`，8,920 次优化器步，KL 提前停止 0 次。平均每轮 **93,546** 决策、每局 **182.71** 决策。

这是一篇论文后期 stage 决策预算的 **22.5%**，不是 745/300=2.48 个 stage。论文约 544 决策/局与我们的 183/局也不能直接等同为“思考质量”：版本、游戏长度、动作统计/采样方式都不同。

现役链已不属于“只训过几千万步”。一味说“慢只是样本不够”缺少解释力。更关键的问题是：**这二十多亿链上采样中，有多少真正练到了经济循环，而不是重复已有低风险路径？** 完整历史没有保存所有逐动作训练样本，无法把这个数量精确补算出来；正式轨迹只能证明当前执行行为的覆盖。

### 3.3 哪些训练故障可以排除，哪些还不能

当前轮首/末 25 轮平均：熵 0.7065→0.6858，近似 KL 0.00493→0.00416，clip fraction 0.0448→0.0411，rank 分类交叉熵 1.4733→1.4739，anchor KL 0.00495→0.02953。

没有证据支持“这轮没更新”“大多数样本被 KL 丢掉”或“已完全零熵坍塌”。rank loss 是 8 类交叉熵，不是回报 MSE；不能用 1.47 的数值直接断言 critic 失效，后续应按回合、阵容与投资状态检查校准。

论文 anchor 的 100 轮约覆盖 105M 采样；我们当前前 100 轮约 9.4M；300 轮学习率退火约 28M 采样，并且其后仍保留 0.02 anchor tail。相同“轮数超参”并非相同数据时间尺度。它值得消融，但还没有证据证明它是主要瓶颈。

## 4. 当前模型能力：成绩、成长与阵容

### 4.1 正式比较的可支持结论

平均名次 4.9141→4.6895，配对差 −0.2246，探索性 95% bootstrap 区间 [−0.4414,−0.0078]。夺冠率 8.40%→12.70%；前四率 40.23%→43.75%，前四差的区间跨零。**有小幅结果改善，没有证明中后期运营取得突破。**

T12 全体幸存者 P50 1287→1352，但共同存活的 270 对是 1311.5→1322，约 +0.8%。不能把幸存者更换造成的差异全算成成长。T16 共同存活仅 7 对，无法可靠判定尾局能力。

原正式 panel 的分位数使用离散顺序统计量，偶数样本可能取一个中间观测；例如候选 T16 官方 P50=4826，两个中间值平均为 4964。本报告主表保留封存口径；新分析若用 `statistics.median` 会明确标注，**不改写原报告或混用两种数字**。

### 4.2 已经学到的东西

T12 候选的高频随从包括希望信使、青铜守卫、蓄能女沙皇、赤红守备巨龙、坠落的飞天魔像、梦魇茶客、胡蒙格斯、执念诗心龙。它们之间存在实际协同，不能称为“随机杂鱼”或“完全不会乘法成长”。

即使组合出现也不代表已正确运营。以0/512为例，只能说在本次argmax/该场地下没有观察到；不能声称策略数学上永远不会形成这些组合，也不能套用一个没有种族资格条件的“掌握概率”区间。

**经济实际支出**使用 EndTurn 动作**之前**的原生 `gold_spent_turn`；EndTurn 之后有时已进入下一回合、计数清零并发新金币，不能读错时点。

可追查实例（索引为每局从0开始的action_index）：seed930004/T10/index68，10金币、罗杰斯与铜须同时可买，选择刷新；seed930000/T10/index111，6金币、罗杰斯可买，选择刷新。它们是整体偏好的实例，尚无多随机后续反事实证明该步最优动作应是什么，**不标为已证实战略错误**。

按全部正式动作分期，候选T1–5及选英雄等早期13944、中期T6–10为46468、T11+为37168（38.09%）。不能说“模型根本没经历后期”；更准确的是：**经历了后期，却很少走到所需的经济状态和动作链。** 这是评测行为分布，不能冒充全部训练样本的分期统计。

## 5. T9–T12 与六本之后为什么停滞

### 5.1 六本已经基本达成，缺的是把六本机会变成循环

首次六本的回合中位数为 T9，到达率 500/512；T9 后动作数增加，但 T10–T12 典型回合仍约 24–26 动作。评测没有因 100 动作上限强制结束回合。T6+ 末金币≥3 的回合为 0。

因此最直接的诊断不是“没花钱”或“动作上限太低”，而是**钱花在什么上、能否再生产资源、是否为循环留出了场位、是否知道何时保留或出售关键组件**。满场且手里留牌不必然是漏打：已有两个 T12 实例在结束时原生 Play 都不合法，必须先卖场上牌。这是机会成本决策，不应通过“手牌必须清空”规则硬解决。

### 5.2 输入缺少可见的机制状态：已验证的表达限制

`engine/crates/hsbg-engine/src/obs.rs::push_minion` 编码身材、星级、金色、附件**数量**、圣盾与种族；没有编码 `Minion.counter` 或附件身份。全局仅选择部分 stats。`entity_model.py` 是当前状态前馈网络，没有动作历史记忆。

本轮 CPU 构造两个合法可推进的研究状态：同一罗杰斯、同一手牌/商店/金币，唯一差异是罗杰斯 counter=0 或8。两者观测字节与合法掩码全部一致；都执行花1金币刷新，结果分别是手牌仍为空和获得一张悬赏令，counter分别变为1/0。**相同输入对应不同下一步经济收益**。这是合成机制探针，不冒充自然评测局，也不据此计算胜率损失。

遗漏并不限于罕见罗杰斯：候选完整轨迹累计13,617次非零counter希望信使的“随从—动作”暴露；同一动作可有多张，因此不是不同动作数。其源码明确用counter决定战斗开始时全场增益，玩家可从动态牌面文字看到它；模型只能从其它数值间接猜测。这个暴露计数不等于独立样本或已经证明受损的决策数。

额外修改 `elementals_played`、`cards_played`、`gold_spent_turn`、`eternal_knight_deaths`、`undead_atk`、`volumizer_atk`、`golden_played`，当前观测及掩码仍相同。这些是“没有进入观测”的验证，不代表每个字段在每种局面都应直接输入；设计时要逐一确认真实玩家可知性，绝不能输入未来商店、RNG 或未揭示对手手牌。

网络侧还有第二层压缩：对手历史战团只用数值 mean/max，没有使用其逐卡身份；待选来源卡等部分已编码 card slice 没进入当前 Entity 主干；Move 的点积头是对称的，两个方向的分差只剩固定 bias。后者与反复换位有关，但不能据此认定它是身材增长不足的主因。

模型不是完全没有卡牌文字：实际 checkpoint 的 `card_text` 为 3984×64，3754 行非零；实现是字符三元组 hashing。论文只说明规则文本 embedding，没有公开训练代码，不能声称两者语义能力等价，也不能反过来断言论文一定用了某个大语义模型。

### 5.3 教师教会了升本，没有教会运营

当前教师标签 887,471，占全部采样约1.27%；目标只到 `2:2,5:3,7:4,8:5`，纯辅助 CE，实际强制动作0。它不会给“买铜须、留空位、循环免费牌、选择倍率目标”打标签。

教师的 `forced_teacher_coef=0.1` 生效，`teacher_bc_coef=0` 不代表全部教师关闭；末段教师 CE 已很小，也不能仅凭 coefficient 大就断言教师压倒了 PPO 梯度。更有把握的结论是：**当前监督覆盖的技能，恰好是已经基本解决的升本，而不是欠缺的中后期经济。**

### 5.4 对手难度与目标造成的投资窗口：强假设，不是已证实唯一根因

候选正式实际遇到的非 ghost 对手 P50：T9=345（n484）、T10=890（453）、T11=1573（398）、T12=3028（311）、T14=5925（150）。己方官方 P50分别346/564/917/1352/2709。T12 对手约为己方2.24倍，候选该回合战斗胜率30.7%、平均受伤9.16；到T14只剩169/512。

这支持“买一个即时身材弱的经济核心，容易来不及回本”的解释，但**均名次接近4.5不等于没有梯度**，攻血差也不是战斗胜率差；不能照搬旧文档“场地掐死全部训练信号”的绝对说法。

当前建库是跨原回合按身材强度筛选，改写目标 turn；T12来源可跨T7–T17。p50band再把强度压进0.45–0.55分位带。这样能控难度，但不能保证经济水平、亡语/烈毒/圣盾、手牌和连续成长结构与该回合真实对手一致。论文的分级、实际遭遇校准不能简化成一个“越高越好”的 P50 数字。

参数名也必须按实现解释：`ban-trinkets=1` 当前只屏蔽指定“加重护手”选择，**不是禁用全部饰品**。攻略中依赖其他饰品/神明的机制仍需逐局检查，不能因参数名而宣称训练环境没有这些机制。

### 5.5 奖励、PPO 与信用分配

终局效用为 `1,.35,-1,-1.15,-1.3,-1.45,-1.6,-1.75`；2→3 的差是1.35，1→2仅0.65。这是用户冻结的目标，不是实现 Bug；它会偏好能改变前二概率的路径，而非直接追求每回合身材。如果一项运营投资目前不改变这些结果，PPO 没有义务按攻略奖励它。

GAE 使用决策时间、γ=1/λ=.995。不能误称“奖励按 γ 消失”：γ并未折扣。按正式轨迹粗估，T9起到终局剩余动作中位117、T12为64，对应 λ 幂约0.556/0.726；这只是末端 TD 残差的权重示意，**不是完整 advantage，也不是梯度占比**。当前记录没有保存逐动作训练 advantage/梯度，不能声称已证明信用衰减为首要瓶颈。

多步循环需要在短期卖掉身材、保留弱组件、制造场位，然后经过多次行动兑现。只有单步随机探索、终局奖励和原模型 anchor，容易反复采到已有局部策略。这个机制解释与当前行为覆盖相符；但要通过同起点的有标签/无标签消融确认，而不是直接更换 PPO 算法。

## 6. 推荐的下一轮路线与小实验

以下均为**待用户批准的研究建议**，不是已生效配方；本轮没有执行这些训练。当前模型、原协议和原库保持可复查。

### P0：把关键状态辨识问题做成小型机制考试

先补一份输入覆盖清单：可见计数、待选来源、法术/附魔具体参数、磁力身份与永久收益、自己已发生的操作历史。优先验证攻略中的经济发动机，不追求把整个 engine JSON 喂给模型。

新输入必须单独版本化；用新字段投影零初始化/旧通道拷贝证明起点策略等价，保留旧 encoder 与 checkpoint。卡序、动作语义和输入布局都纳入 manifest；这会涉及科学架构，须批准后再实现。若信息可直接观察，优先显式编码；只有必须依靠历史恢复的部分再考虑小型 recurrent memory。

低成本验收：约128–256组反事实状态对，除目标机制外全部相同；验证字段可区分、原生一步结果符合规则、无隐藏信息泄漏。模型训练前就能先测输入上限。已有罗杰斯探针是其中一个最小反例。

### P1：学习可兑现的经济过程，替代“买核心卡给分”

先选三个可迁移的机制模块：

1. **循环经济**：罗杰斯/私掠者/铜须相关的资源生产和低净成本循环；
2. **倍率兑现**：战吼复触发、定向法术重复、酒馆强化向场面搬运；
3. **场位与目标管理**：何时卖最小贡献随从、腾一个循环位、保护关键发动机、把成长落到合适承载者。

从**新的训练源自然对局**保存 T7–T12 原生状态，生成少量有因果依据的候选短计划；用 simulator 分支验证每个原子动作是否合法、经济账与机制收益是否真实，再用不同后续随机性检验可迁移性。计划建议由攻略提供，标签必须由真实执行验证；不能把 LLM 文本意见直接当专家真值。

先做“会操作已成型发动机”的局部题，再做“缺一个组件如何接上”，最后做“从普通过渡场面识别是否值得投资”。逐步扩大状态分布，同时保留自然整局训练。**不再次复制旧入场课程**：旧方案从人类片段注入、常由bot打前缀、曾有注入率问题；这里优先原生可恢复状态、过程验证和明确技能标签，且必须证明局部能力能迁移到从T1开始的整局。

监督采用 DAgger/专家迭代思路：让当前学生访问状态，再对其真正遇到的偏差补标签。旧 C1 的 BC 负结果来自不同输入/数据/混合入场配方，不证明所有行为学习无效；本次可重试的理由必须是**新验证标签与新状态覆盖**，而不是把旧BC系数再打开。[DAgger 原文](https://proceedings.mlr.press/v15/ross11a.html)、[Expert Iteration 原文](https://proceedings.neurips.cc/paper/2017/hash/d8e1344e27a5b08cdfd5d027d9b8d6de-Abstract.html)

旧33流派覆盖统计使用缺卡的49卡映射，本轮解析为84张不同核心卡；两者百分比不能直接纵向比较。继续保留既往奖励投机负结果，不因为映射改进就重新启动“凑卡奖励”。

不要把本轮正式 held-out 轨迹变成训练标签；它们只作诊断。训练状态、开发题、最终独立题按来源与 seed 分离，近重复局面也不能跨集合。

### P2：在技能可用之后，以分级对手和整局 PPO 接回长期目标

建议先保留现有终局效用和 PPO，避免同时变奖励、网络、对手和探索。若局部技能已学会、整局仍不投资，再单独比较当前压力与“当前难度/稍易/稍难”的分级混合。测量**学习者实际遭遇**的战斗胜率、剩余寿命、核心到手后的兑现概率；不要只按库里均匀抽样的攻血设目标。

不立即改成纯自博弈：它可能继承相同缺陷，并增加非平稳性与算力成本。当前库保留为固定参考，对手群体化在技能出现后再做；人类示范与群体训练结合有其他复杂游戏的先例，但不能保证酒馆直接复现。[AlphaStar 作者说明](https://deepmind.google/blog/alphastar-mastering-the-real-time-strategy-game-starcraft-ii/)、[SCC 论文](https://proceedings.mlr.press/v139/wang21v.html)

### P3：按证据决定是否改变信用分配、奖励与输出头

优先记录分回合/机制的 critic 校准、advantage 符号、投资动作后2–3回合收益、PPO/教师/anchor梯度范数。若终局 critic 无法给经济投资合理区分，再考虑过程价值辅助头、turn-aware信用分配或多步价值学习。它们首先是辅助预测任务，**不自动改奖励目标**。

不推荐重新启用 comp-target、无门控升本奖励或 retained_growth。既往已出现买核心后不兑现、升级挤掉场面等捷径。若未来确需塑形，应独立研究势函数形式、终止边界和新回报是否改变原目标；不能把“身材增量”随便加到奖励上就称为无偏。[势函数塑形原文](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)

有向 Move 头、独立 Sell/Activate 头、语义文本表示、短回合规划都可作为后续消融。优先级低于输入覆盖与经济样本；论文已经说明约18M网络可很强，没有证据要求立即换大模型。也不直接把老PPO样本做无限离线回放；它们不是当前策略采样，需适当离策略处理或只用于有验证标签的辅助训练。[PPO 原文](https://arxiv.org/abs/1707.06347)、[GAE 原文](https://arxiv.org/abs/1506.02438)

### 建议的最小训练验证矩阵

| 阶段 | 对照 | 建议预算与门槛 | 能得出什么 |
|---|---|---|---|
| 机制验证 | 当前输入 vs 可见状态扩展 | 128–256组状态对；无GPU训练；动作/状态核验100%通过 | 输入是否足够、标签是否可信 |
| 学习方向筛选 | 原输入/扩展输入 × 无新标签/有验证标签，2×2 | 每臂3个seed、先各2M采样，共24M；所有臂相同算力/数据预算 | 能否学会局部循环；**不足以宣称整局进步** |
| 确认迁移 | 最佳臂 vs 同预算原方法 | 预注册更长的小阶段，例如各3seed×10M；记录中间退化；这是下一次审批的预算 | 是否只是短窗口乐观或过拟合题库 |
| 正式验收 | 原模型与候选，完全同协议/独立seed | 沿用可信512配对规模；先固定停止规则，统计不足就报告不确定，不能挑最好seed | 逐回合M1+n、共同幸存增长、名次、技能覆盖是否一致改善 |

上述24M/60M均为预算建议，不是启动命令；若资源不足先做机制验证和少量标签正确性检验。主筛选指标应预注册，例如独立技能题完成率提高≥20个百分点、资源账无伪增益、自然整局中核心机会转化率上升且前期生存不出现明显退化。阈值是筛选标准建议，不替换现有正式判胜标准；任何效果都要报告分seed波动及区间。

## 7. 两端存储分工：本轮只分析

Windows 实测 D 盘剩余约506.5GB；这不否定用户要求本地轻量化。扫描排除了虚拟环境、release和符号链接，以下为相应范围的文件逻辑大小：

| 类别 | Windows | NUS | 判断 |
|---|---:|---:|---|
| runs | 23.22GB | 189.25GB | 本地存在较多历史运行资产；服务器是主要容量来源 |
| models | 9.84GB | 7.85GB | 本地反而比服务器大，历史副本/嵌套版本不符合未来轻量定位 |
| libraries | 0.36GB | 0.39GB | 库本身不是主要空间瓶颈，优先删库收益很小 |
| imports | 3.86GB | 未列入主要项 | 应先做重复/恢复依赖清单，不能直接当垃圾 |
| archives | 3.72GB | 0.22GB | 位置不同，不代表服务器没有历史资产 |
| evidence / archive records | 本地 evidence 5.31GB | 远端 records/archive 22.42GB | 证据和旧格式模型需要保留来源关系 |

Linux再按inode去重、计实际占用块：runs约159.37GB、records/archive约19.68GB、models约7.05GB；硬链接/稀疏文件导致逻辑字节与 `du` 不同，**不能把逻辑大小直接当成可释放容量**。共享home约94%占用，用户在共享文件系统上的真实配额仍待确认。

建议未来采用：

- **本地热区**：源码、CPU管理环境、研究报告、轻量索引、验收时所需的一个模型、必要恢复清单；实机恢复前不再同步整套训练资产。

## 8. 复核材料与尚未解决的问题

本地研究材料在 `artifacts/state/research-20261117/`，服务器同名目录保存扫描脚本、账本和逐动作压缩摘录；原始大证据仍只留服务器。材料身份与复核入口见附录。

尚未解决：

1. 训练历史前4159个update缺逐行原始证据，完整实际梯度消费量、真实GPU小时无法精确追溯。
2. 正式执行是argmax，不能据此计算训练随机策略探索到经济循环的频率；需要下一次获批实验记录训练态覆盖。

4. 对手压力、奖励形状、anchor与缺乏示范的贡献不能由现有相关性完全分开。
5. 策略级指南不是完整动作专家；新的过程标签必须经过原生执行、随机后续和独立状态验证。
6. 所有科学变更仍待用户决策；本轮没有把建议悄悄写成默认配方。
