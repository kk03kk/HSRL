## A. 法术自举补贴（spell bootstrap subsidy）—— 2 小时，直接对着已量到的病灶

**要修的现象（已量化，RUNS §5.54/§5.57/§5.58）**

| 事实 | 数字 |
|---|---|
| champion 整局买/打法术 | **0 / 0**（96 局，`buy_minion == buy` 精确相等） |
| 同批真人（tier≥5 帧） | T8 每回合买 0.46、打 2.28；T12 买 1.51、打 5.58 |
| 入场课程给的 T8 帧里"手上有法术"的比例 | **29.1%**（所以不是状态缺失） |
| "买法术"这个动作是否合法 | **合法**：`N_SHOP=8`，法术槽 = `A_BUY+7`，每次刷新都填（`recruit.rs:325`） |

⇒ 结论：**策略从未探索过这一整类动作**。名次奖励是终局稀疏信号，单次法术对终局名次的影响
被 200+ 个决策稀释，梯度≈0，所以它永远不会自己学出来。

**设计（最小干预，可回退）**

- 新配置键（默认 0 = 与旧路径逐位一致）：
  - `spell-bootstrap-coef`：奖励系数（建议 **0.05**，相对 rank utility 的量级 ~1.0）
  - `spell-bootstrap-per-game`：每局最多奖励几次法术动作（建议 **3**）
  - `spell-bootstrap-until`：只在前 N 轮生效（建议 **400**），之后自动为 0
- 作用点：`hsbg/az/train/reward_shaping.py` 增加一个**动作条件**奖励项（非势函数，
  **不满足策略不变性**，必须在配置与日志里显式标注），由 collect 侧在写 `record["reward"]`
  时按"本局已触发次数 < K"追加；PPO 侧不需要改（它已经在加 `rec["reward"]`）。
- 接线清单（与 `keep_start_board` 那次同样的坑，别再漏）：
  1. `reward_shaping.py`：字段 + 计数逻辑 + `format_*` 便于日志；
  2. `ppo.py::CollectConfig`：三个字段 + `__post_init__` 校验；
  3. `personal.py::OPTIONS`：三个键（否则 `validate_config` 直接拒）；
  4. `train_entity_sync.py`：三个 argparse + 打印 `[spell-bootstrap] coef=… K=… until=…`
     （**必须打印**，否则会像 `board_target` 那样配了没生效却跑完一整段）；
  5. `evaluate.py`：面板里统计 `spell_bootstrap_hits`，确认补贴真的触发过；
  6. 测试 4 条：① coef=0 与旧路径逐位一致；② 每局只奖励前 K 次；③ 超过 until 轮后为 0；
     ④ 只对法术动作（`buy_spell`/`play_spell`）生效，随从动作不加。
- **判据（先登记，不许事后改）**：跑 300–400 轮后，96/192 局真人场里
  ① `play_spell` 从 0 变成 **>0.5/回合**；② T11 板面 `cand/base ≥ 1.15`；
  ③ `mean_rank` 配对 CI **上界 < 5.4375**（即显著优于 champion）。
  只满足 ①② → 保留但继续加长；③ 不满足且板面也没动 → 判负、关闭该项。

**风险与对冲**：可能被"刷廉价法术"骗分。对冲 = 每局配额 3 次（不可通过多打获益）+
400 轮后退火为 0 + 验收同时看名次。

## B. z 流派条件化（comp conditioning）—— 1–1.5 天，抄第三方唯一先进结构

**依据**：第三方（`PrentendYan/hearthstone-bg-ppo`）的 `TavernNetCZ` 用 46 个流派 token 做条件化
（`z_global` 加到全局 token、`zcard[46,3984,3]` 投影后加到每个卡嵌入），自报 T12 板面 ≈ 真人中位数
（我们用同口径量到的 champion 只有真人 **27.5%**）。它自己也承认"偏科野猪人"——即**专精**是它的强度来源。

**设计**

- z 词表：我们的 33 个流派（`config/strategy_cards.json`）+ `none`，共 34 类；
- 卡标志：每卡 2 维（是否该流派核心卡 / 是否该流派可用卡）→ `zcard[34, n_cards, 2]`；
- 注入：`z_global`(34→d) 加到 **global token**，`z_tok`(2→d) 加到 **每个卡嵌入**（与第三方逐位同构）；
- 训练：每局开始按 `z-p`（建议 0.5）采样具体流派，否则 `none`；
- 推理/评测：分别跑 `none` 与每个流派，报告"最优 z"与"none"的差；
- 需要改的 digest 文件：`entity_model.py`、`ppo.py`、`personal.py`、`train_entity_sync.py`、`evaluate.py`。

**判据**：同样四件套 + "最优 z 的 T12 板面 ≥ 1.3× champion"。

**为什么排在 A 之后**：它改的是输入结构，成本高 10 倍；而 A 直接对着"已量到的 0"，
两小时就能给出是/否。若 A 成功（模型开始用法术、板面变厚）而名次仍不动，再上 B。

## 修订（2026-11-14 00:55）：改成**两臂并行**，而且都从 L4 的 checkpoint 起跑

`RUNS §5.62` 把真人中后期增长拆开之后发现：**≈90% 的增长来自"养留存随从"（+690/随从/回合），
换牌只占 ~10%**。这让原计划里"先 A 后 B、K=3/局"的顺序需要修正——K=3 的补贴只够"点亮动作"，
而目标是每回合多出 ~1,300 属性，量级差得很远。所以改成一次跑两个机制臂（各占一张卡）：

| 臂 | 配方 | 信号类型 | 预期代价 | 判据（先登记） |
|---|---|---|---|---|
| **L5a 补贴臂** | L4 配方（lr 3e-6、anchor 0.02）+ `spell-bootstrap-coef 0.05` / K=3 | **动作条件**（非策略不变） | 几乎为零 | `play_spell` >0.5/回合；留存增重 ≥+150 |
| **L5b 塑形臂** | L4 配方 + `shaping-coef 0.1`（`log_strength`、`w_tier 0`） | **势函数**（gamma 对齐 ⇒ 策略不变） | ppo 相位约 2×（S1b 实测 84 s/轮 vs 51 s） | 留存增重 ≥+150；T11 板面 ≥1.15×；rank CI 上界 <5.4375 |

两条都从 **L4 的 checkpoint** 起跑（L4 是唯一"策略真的在动"的臂，§5.61 已证），
启动器统一用 `deploy/slurm/spell_l5.sbatch`（`HSAI_LR_CKPT` / `HSAI_SPELL_COEF` / `HSAI_SHAPING_COEF` 全走环境变量）。

**为什么值得同时跑**：这是"动作级探索"与"结果级塑形"两条互补路线的最小对照实验，
以前都只被"冻结的 lr"污染过（S1b 只有 114 轮、生效 lr 1.667e-6）。
如果两者都失败 ⇒ 说明问题不在信号而在**容量/结构**（那就上 z 条件化，见 B）；
如果只有塑形臂成功 ⇒ 说明"给成长本身发钱"是对的，以后所有奖励都按留存增重设计。

**复用提醒**：`shaping_coef>0` 时必须 `shaping-w-tier 0`（否则 tier 奖励表 900 会盖过强度项，
S1b 踩过：`adv_std` 从 0.15 飙到 16.2）；`spell_coef>0` 只认 `A_BUY+7`（买法术），不认打法术。
