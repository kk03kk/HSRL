## 2. 会影响下一轮的具体问题

1. **状态命令的成功退出码不能作为同步门。** `cmd_state` 只看来回 SSH 探活是否成功。用临时目录和模拟返回值分别注入远端状态读取失败、服务器工作区脏，均得到 rc=0；展示层虽区分 ERROR/DRIFT，自动启动器若只检查 rc 会放行。当前工具的 push 又只允许 main，而活跃研究分支不同。建议保留人的状态视图，给提交入口增加显式的 fail-closed 校验，同校分支、完整 HEAD、两端 dirty、远端查询状态。不要通过切换 main 处理。状态读取还包含全库 `du -sh .`；把容量统计改为低频采集可独立于每次 SSH 探活验收。[状态与推送入口](../../ops/hsai_ops.py)
2. **两端都有 5 项失败。** 三个 anchor 测试只截取 sbatch 的参数拼接段，夹具遗漏 `move_guard/move_repeat/max_actions`，在检查续训参数前就因 unbound variable 中止。只在内存中补齐夹具，三个原断言均通过。另两项测试把新增的 `--lobby-filter-probability` 算进冻结旧接口；排除该项和原已登记的两个课程选项后，旧 263 项完整摘要仍是 `6c74880e…35fec43`。修复应保留旧摘要，再单独断言新增参数的默认值 1.0 和传参语义；不能只放宽计数。Linux 对这 5 项的定向运行全部复现。[分段测试](../../tests/test_arena_segment_anchor.py) · [CLI 契约](../../tests/test_training_cli_contract.py)
3. **运行真值分散且易选错。** 仓库 AGENTS 和默认 sbatch 仍描述 100 步/2 次换位的旧契约，当前群友场为 200/10。Python 在导入时读 profile；实测先导入再设标准 profile，同进程得到的契约仍是 100/2。D-155 封存的 `identity.settings` 仍写 v1.4-r1 和 iterations=0，而 `plan.runtime`、真实命令及 SHA 证明执行的是群友起点和 8+52 批。统一生成一份已解析的模型、种子、动作、奖励、预算与环境清单，同时供 sbatch、评测和恢复使用；未知 profile 直接失败，清楚标记旧入口。此前结果有额外证据可以区分。[评测契约](../../hsbg/az/train/eval_policy.py) · [试训入口](../../workflows/peer_open_ppo.py)
4. **同协议指纹不足以单独证明同场。** 协议序列化包含场地路径、规则、引擎和尾帧策略。单独启动的群友留出评测检查协议 SHA 和 5,477 帧，未在该检查中与预期库内容 SHA 比较；相同路径和帧数可对应不同内容。训练入口已有内容校验，本次也实算相符。将已实现的库摘要校验前移到每次独立评测与分片复用，另记奖励表 SHA、指标版本与来源切分，保留历史榜号。汇总还写死 T6–T18；原分片中候选有一局走到 T20。应报告所有有记录的回合并标尾帧。[留出检查](../../workflows/peer_finetune_holdout.py) · [汇总](../../tools/summarize_peer_finetune.py)
5. **研究目标与扩训条件需要同时写清。** 项目将逐回合 M1 和增长列为主指标，D-155 实际奖赏和扩训第一条件却是终局名次效用，T12 只做不劣检验。第二与第三名奖差 1.35，第一与第二差 0.65。这适合检验保二，不会单独确保提高后期成长。下一项若研究保命，预先声明保命收益和成长保护；若研究成长，要求共同存活 T9→T12 的增长改善，同时保护到达率与终局效用。对既有 D-156 仍用其事前判据。[项目评测约定](../EVAL_PROTOCOL.md) · [D-155 判据](PEER_OVERNIGHT_AUDIT_20261119.md)
6. **七个真人快照席能检验局内经营，但覆盖有边界。** 七席按回合重新抽可见盘面，同一对手跨回合的投资、真实手牌、英雄与隐藏成长未完整恢复；原记录玩家与其原对手分布也不同。训练实帧到 T20，留出到 T18，启用最后观察帧后的名次需报上下界。D-156 只有候选一局受此影响，最保守效用点估计仍是 +0.0183。长期在这 278 个原局上选方案会把留出库变成开发环境。正式晋升应另留未参与选方案的来源分块，按原局与历史来源去重；对手分布改变时独立报告。[建库与限制](HUMAN_TURN_BASELINE_20261118.md) · [实际遇敌分析](HUMAN_FIELD_BY_TURN_20261119.md)
7. **恢复到新机器还有外部依赖。** `peer_heads_v1` 的加载会导入 Git 外作者网络代码。NUS 内容校验通过；本地有原始权重，标准参考源码目录本轮查无。作者权重的引擎指纹是 `205739107f78dc5a`。索引富集、卡表关联、同源动作、真实对局和包装等价均支持当前用途；作者权重元数据未给出完整有序词表的独立摘要，仍不能把局部验证外推到每一个索引。将作者固定版本、代码文件摘要、来源、卡表与包装代绑定到研究模型卡，在空目录验证重建。现有 reference manifest 的“optional / 来源未验证”描述亦落后于 D-150 的已登记资料。[外部依赖验证](../../hsbg/runtime/references.py) · [参考清单](../../config/reference-assets.json) · [作者资产核验](PEER_PPO_20261119.md)

## 4. 下一项实验与扩训条件

**首选研究方向是用冻结权重验证低血量时的后段决策能否产生可用的整局收益。** D-156 的 68 个原版开局低血中局，候选后段效用 +0.168 [0.063,0.287]；旧协议在群友自己的中局方向相近，而从 3265 开局接管曾出现相反方向。它提供了可证伪的具体假说，暂不足以将第 60 批设为通用起点。

1. **先修工程入口。** 修复上述两组测试并保留旧契约断言，让 Windows 与 NUS 的目标测试转绿。新增实际 profile 生成/拒绝测试、独立评测库摘要检查和可靠的状态退出码。生成一份供训练、评测和恢复共用的冻结计划，按 D-156 对同一输入对照。预留独立来源，记录来源游戏、角色一侧和各回合覆盖；缺少可信独立来源时，只报告对现有库的有效性。
2. **先用冻结模型做一次事前登记的策略对照，无需任何梯度更新。** 主臂从群友原版正常开局，首次在 T9–T12 回合开始、注入完成、首个决策前，看到自身生命加护甲 ≤15 时，切到 D-156 第 60 批直至终局。对照全程原版。两臂共享大厅种子、对手抽样规则和生效的动作守卫；切换保留控制器状态，未触发局必须逐局相同。不得按事后胜负、阵容或未来选局。固定两个参照来源（原版开局为主，自有 3265 开局只作迁移诊断），报告触发率、触发前一致性、触发人群和全体结果。先在开发来源验证控制器与触发频率，再封存权重/阈值，正式对照用未用于选该规则的来源和种子。
3. **用实际意义确定规模。** 建议最低值得扩大训练的整局效用差定为 +0.10（研究预算决策值），沿用已测逐对标准差 1.049、双侧 5%、80% 功效，正态近似约 863 对；预先取 1,024 对，一次判定。新来源或切换臂的方差可能不同。开发阶段先估触发率与有触发局的配对方差；全体收益等于触发率乘触发局平均收益。例如触发率若为 30%，全体 +0.10 要求触发局平均约 +0.33。若开发估计显示这个量级不值得追，立即封存并结束，省下确认面板。68 个选中中局不能用来直接估计自然整局首次触发率。这一规模不适合声称排除 +0.02 的小收益。报告每个模型前二、前四、冠军、末位、各回合 M1/M2/样本数、共同成长、T12 到达率、尾帧界限。保命假说要求全体效用点估计至少 +0.10、配对 95% 下界 >0、共同 T12 对数强度下界 ≥−0.12；保留共同增长曲线。若结果只在低血子组显著，停止扩训，保留诊断；若冻结切换已达到目标，直接保存组合策略作研究基线，先评估新增训练的边际价值。
