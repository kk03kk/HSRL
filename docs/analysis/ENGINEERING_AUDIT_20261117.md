## 6. 尚未解决的风险与部署条件

1. **运行时不可变性（高）**：现有训练从共享工作区导入。新推送守卫仍是客户端检查，直接 git push、显式覆盖开关、检查到推送之间的调度竞争都不由它彻底防住。建议后续每个作业固定源码/依赖发布目录，并增加服务器侧提交检查；本次不改活跃环境。`state` 的退出码主要表示隧道健康，DRIFT 仍需读取结构化状态/doctor，不能只检查 rc=0。
2. **部署与恢复（高）**：本次改动覆盖 `training_source_digest` 范围。不得把新代码直接接到旧 trainer 上并绕过 digest。等无运行/排队依赖后，保留旧代码+环境用于精确恢复，再部署新的独立发布目录；同一训练恢复需要旧 digest。CPU 通过不替代服务器 CUDA 恢复/AMP 验证。
3. **发布的原子边界（中高）**：版本化 `latest.json` 指向同代快照，应优先通过它解析 model/trainer。根目录的两个别名顺序发布，读取它们可能跨代；最终导出也是多文件过程。评测/导出现在遇错停止，但不是抗断电的多文件事务，也没有全局并发运行锁。失败产生的 partial 保留，不能当成功产物；两进程争用同目录仍应避免。
4. **保存历史有限（中）**：现役脚本 `snapshot-every=5 / keep-snapshots=3` 自动轮换旧快照。历史日志保留不代表全部历史模型仍存在。未更改当前存储策略，后续里程碑证据保留需求要与磁盘预算一起制定，不能临时把全部快照永久保留到共享盘。
5. **完整恢复范围（中高）**：Trainer 保存模型、Adam、调度/RNG/anchor 等状态，但分布式 worker RNG 和已在途的 pipeline 批次是否构成完整可重放状态，尚未通过 CUDA 故障恢复试验确认。“加载 trainer”不应自动等同整条分布式轨迹逐位复现。
6. **协议身份仍不完整（中高）**：协议包含场地路径和参数，但不绑定快照库文件内容 SHA。原路径下替换内容可能仍同 hash；legacy hash-only 证据没有完整正文可复核。添加内容身份会改变协议/换榜，本次只记录，不偷偷改协议定义。
7. **统计历史不可自动修复（中）**：老日志缺全局原样本，不能从 worker P50 还原真实 P50。修复只对新代码生效；已有训练日志及未部署期间继续产生的 P50 不可事后冒充精确值。部分对手均值/arena band 统计仍缺可靠分母；旧 multi 合并器的部分聚合字段存在舍入近似。判胜优先采用有逐局/逐回合原始证据的重算值。

## 7. 训练设计分析与建议（仅建议，未修改）

论文核对依据：[AutoTavern 论文](https://arxiv.org/html/2610.33845v1)、[作者仓库](https://github.com/MCG-NJU/AutoTavern)。Table 7 支持 lr、clip、KL、GAE、梯度裁剪及 anchor 前期系数等对照；原文未明确跨 stage 恢复 Adam，因此此前“论文包含优化器恢复”的断言改为待确认。论文按实际遇到的对手统计校准，并使用独立来源的 held-out；这比仅比较库文件本身的中位数更贴近训练暴露分布。

- **用决策量而非轮数理解预算。** 当前约 9 万决策/轮，与论文约百万/轮差一数量级。相同 100 轮 anchor 不是相同经验量；本项目还有 tail 与教师损失等差异。建议先统一记录决策预算、优化步、梯度累积和 anchor 的经验覆盖，再由用户决定是否调整，不能宣称已完全复现论文。
- **奖励信号弱仍是假设。** 平均名次接近 4.5 不证明无梯度；应分析回报分布、条件方差、优势量、不同回合的强度与未来名次/存活关系，同时区分混杂与因果。不要仅凭一个 R² 就决定改奖励。
- **强度刻度有选择偏差。** 逐回合 M1 是存活条件下的 P50；共同存活子集能帮助比较但也会选择样本。应同时展示样本量、存活率、逐 seed 配对差、增长与名次区间；winner-biased 真人样本不是普通玩家均值。
- **多参数 OOD 结果不能作单变量归因。** D-073 同时改变动作预算/move/freeze 并使用旧契约模型，不能证明每一项各自的因果效果，也不能从旧上限触发少直接证明“提高上限无害”。该条写出的点估计 Δ+0.424 与区间 `[+0.545,+0.703]` 不一致，正式引用前需按同 seed 证据重算；旧决议保留，D-077 追加勘误。
- **先使用当前长训已有产物。** 待用户决定评测时，按同契约、同权重身份、冻结 held-out 与成对 seed 判断，不启动额外“确认复现”轮次。奖励/课程/场强/模型输入/动作 cap 的后续实验应单变量、明确预算，由用户决策。
