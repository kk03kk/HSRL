## 模拟器与训练机制

- 模拟器 `move_minion` 移动真实实体，招募时函数本身只重排。冻结键统一切换现有卡位，没有金币消耗。Player150 允许每招募阶段三次换位、冻结与解冻合计两次。限制同时在采样前掩码或引擎生效。实机按已成功回执记账。
- 原守卫按动作号比较立即反向，且 Player150 同一个动作号允许重复。因为槽位里随从会换，动作号本身不足以确定是否回到原局面。冻结的次数限制也只阻止第三次按键，两次仍能还原同一商店。
- 3286 冻结训练的 `run.env` 记录名次终局效用、额外升本奖励关、`sims=0`。启动脚本 `gamma=1.0`，采集默认 `step_penalty=0`。除总步数与独立次数用尽，等价换位或原店冻解没有专门时耗代价。在实机它们会花手势和确认时间。这个差距给循环留下空间，无法单独证明循环由某一项训练设计造成。
- 3286 的观测有总剩余步数、当前棋盘与逐卡冻结。独立的换位或冻结剩余额度没有数值输入，动作耗尽时才能直接从掩码看见类别消失。

## 修复顺序

1. 先试动作前防护。用本回合连续换位中真实实体的顺序屏蔽回到已见盘面的候选。出牌、卖牌或经营动作后重开记录。冻结只针对空商店及连续两次将同一商店恢复到原逐格冻结状态的操作。改变商店或有独立决策之后仍能解冻和重冻。
2. 再试让策略减少耗时。屏蔽绕圈后仍经常选别的换位时，独立试验小额的执行时间成本，或让模型明确选择结束连续排位。报告实机观测到回执耗时、空转、最终站位、战斗与终局质量。继续允许能形成新盘面的换位，保留嘲讽、圣盾、亡语等站位收益。
3. 如果三次换位和两次冻结继续作为固定规则，新训练模型可增加两个数值 `remaining_moves_this_turn` 和 `remaining_freeze_toggles_this_turn`。成功动作扣减、回合切换重置、实机按回执记账。它们能帮助策略规划保留次数。防重复状态仍由完整站位和冻结记录实现。单独对照次数输入、执行成本和防重复掩码，保留旧 schema 以便继续复现 3286。
