# HSAI R1 酒馆战棋控制台

## 启动和操作

1. 打开炉石，进入有「开始」按钮的单人酒馆战棋大厅。使用已校准的 2560×1600 客户区和 144 DPI。
2. 双击 `client/start-ai-control.cmd`，选择「单局」「指定局数」或「连续运行」，点击「开始匹配」。
3. 用 `Ctrl + Alt + P` 在炉石前台暂停或恢复。「正在收尾」表示仍有目标选择、确认或回执待处理，看到「已暂停」即可接手。暂停期间炉石继续计时。窗口里的按钮也可发请求，切回炉石可让尚需画面确认的事务收尾。
4. 「安全停止」和关闭控制台都等待当前事务收尾。已发出的匹配由炉石继续处理，程序保留现场供手动接管。目标局数正常完成时自动返回大厅。点击「打开日志」查看本次运行目录。

控制台使用本机已有的 Python/Tk，启动脚本指向 HSAI 的 `.venv`。实机子进程使用 `fast` 配置，8 个 CPU 推理线程，复用现有的模型、日志、投影、OCR、输入和回执链路。局数按权威终局记录递增。异常时停下并保留现场。窗口和游戏进程各自独立，控制台不占据游戏画面。

## 事务与重连

- 在首个鼠标按下前复核操作员命令。按下后，当前事务可继续完成拖放、确认、目标选择和回执。恢复时清掉候选决策和输入准入缓存，用当前对局日志、窗口信息与新画面再次核对。
- 控制台每两秒更新控制消息。心跳失联约 12 秒后，执行器完成现有事务并停止，结果和回执账本留档。
- 自然掉线时使用炉石原生「重新连接」。这一入口依赖当前日志连接状态、同局身份和重连弹窗复核。连接恢复后重建证据，待确认回执仍按原操作核对。碰到客户端只能重启或无法验证的状态，控制台提示检查炉石并保留账本。
- 本机 HDT 团子版 2.8.2 的游戏叠层可见「一键拔线」。本机的 `HotKeys.xml` 登记了 `Reconnect` 动作，`config.xml` 启用了该快捷键。控制台独立于 HDT 运行，主动断线跳过战斗未集成。
- 实测 HDT 的英雄对比浮层覆盖了执行器的光标停放点。控制台可跳过被挡住的停放点。点击、拖放起点和终点仍必须属于已验证的炉石窗口。
- 控制台重启后，旧进程遗留的事务只读回执；过去的决策无法授权新的鼠标输入。

## 验收与证据

| 项目 | 证据与结论 |
| --- | --- |
| 一键匹配 | 两次从控制台进入真实单人匹配。每次启动匹配只发出一次大厅点击，游戏日志分别在 96.4 秒和 23.1 秒后确认游戏就绪。 |
| 安全停止 | 第一轮在英雄画面暂停后用窗口内的「安全停止」，退出码为 0，保留日志。该局出现过提示重启的断线屏，未取得同局成功恢复证据。 |
| 暂停与恢复 | 第二轮按快捷键完成四次暂停和恢复。确认暂停到恢复累计 43.56 秒，物理输入为 0。第一段还记录到首个按下之前取消候选动作，恢复后重新推理并获得回执。 |
| 真实操作 | 第二轮完成英雄选择与确认，运行至第 10 回合。184 个已派发决策有 181 个取得因果回执。满手牌处存在已确认的错牌，该局验收暂未通过。 |
| 错牌修复 | 第 10 回合，模型选择满手牌的第 9 张，旧坐标实际选中第 10 张。根据保存画面更新第 9 张的抓取点。用真实回执回放确认新验证器直接拒绝错误实体。更新后的坐标尚待实机复测。 |
| 连续对局和最终返回 | 单局、指定局数、无限运行和到目标后返回大厅的控制逻辑经离线测试。第二轮中止于首局，连续匹配与最终返回大厅未取得实机通过证据。 |
| 离线测试 | 111 项通过，6 项跳过。R1 模型加载、词表、动作契约、兼容推理与闲置控制台均通过。 |

第一轮原始记录在 `artifacts/runs/live-control-20261121-121739-5769e`。第二轮在 `artifacts/runs/live-control-20261121-122256-31d1d`。第 10 回合错牌证据在第二轮的 `match-0001/overdue`、`match-0001/visual-evidence/dispatch/0.jpg` 和 `match-0001/unresolved-input.json`。该局结束前炉石进程退出，原因待确认。按用户后续要求，最后一轮修复验证使用存档回放。
