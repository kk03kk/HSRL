# 模块 2 初审：3286 的观测、动作与模型

2026-11-21。对象为 3286 权重、NUS D-204 验收引擎 `6340d5120e9ddda5`、Windows 实机工作树 `62f5720`。本文核对观测、策略和执行的实际入口，并用冻结权重做固定状态探针。训练配方、代码、模型与实机入口未改动。

## 观测缺口

- 对手：Player150 已屏蔽另外六席及当前对手经营中的私有内容。引擎能看到下一战英雄和曾与此人交手时记录的旧棋盘、等级和回合。实机生产路径通常只填明确公告的下一战英雄；目前不会把旧战团接入该扩展。两次 3286 实机的 141 帧推理，139 帧有对手英雄，0 帧有旧棋盘，6 帧有旧交手回合。仅覆盖到 T7。旧战团在回合末快照对手场里能否帮助战斗和招募，需用配对结果确认。
- 己方：模拟器有八个非宝石成长值（亡灵、甲虫、Volumizer、酒馆元素，各攻血）、宝石质量、商店卡位生命购买标志、动态卡文和附件。实机在该扩展中仅补有日志标签时的宝石质量，141 帧中两项各 51 帧；其余成长与生命支付标志为未知。动态卡文只重建了特定案例，例如罗杰斯、Wrathguard。基础观测另外会估算免费刷新、全局价格、法术或酒馆强化、附件等；对实际可买和选谁仍以执行侧证据为准。高频缺失中，优先核对能直接改变当前或后续资源选择的数值。
- 剩余步数可观察。换位及冻结各自的剩余额度没有专门数值通道；掩码会在用完后移除相应动作。只有被准入的动作才允许推理或派发。

## 动作限制与实际行为

- 原生换位占 196–244 槽；满七格盘面最多 42 个不同的源位到目标位动作。出牌时选插入位置已合进出牌动作，独立换位限制直接约束已在场随从。旧评测 3286 的固定场和真人战团场共 384 局、4,844 个招募回合。T8–T10 有 1,107 个回合，全都做了三次换位。触顶只说明限制常生效。后续对照应衡量更好的最终站位、战斗结果与执行成本，识别同一实体来回、重复棋盘和零收益手势。
- 冻结和解冻复用槽 2。T8–T10 有 254/1,107 回合用满两次，T11–T13 有 548/801 回合用满两次。早期 R1 系列发现绝大多数第二、第三次按键紧挨上一次。其观察用于提出“按酒馆状态变化过滤空转”的假设，不能替代对 3286 的逐动作验证。合法的解冻和买牌／刷新后重冻都可有价值。[旧冻结研究](PEER_ACTION_BUDGET_20261120.md)
- 同一旧评测中，31/4,844 个回合耗尽 150 步，记录包含环境收尾所以成 151 条动作；29 个结束时仍有金币。中位动作数 21。上限主要影响少数长回合。两个实机追踪剩余步数最小为 116 和 137，无法判断后期触及 150 步时的真实结果。[旧评测数据入口](PLAYER150_STRATEGY_EVAL_20261121.md)
- 训练的步数耗尽后，Rust 从剩余合法选项按该局 RNG 处理，再结束招募。实机由回执累计确认的事务步数，耗尽后停手，实际选择与结算交给客户端。只剩一步时实机额外屏蔽需再选目标的手牌法术，Rust 一般可发起并在超时处理选项。玩家的 EndTurn 在实机也代表停止操作并等待。两种时间约束的结果与概率需要独立记录。真实手势执行、分支、回执、重新决策的证据不要从模型的 245 个槽反推。[实机时序审计](PLAYER150_LIVE_SPEED_20261121.md)

## 固定输入消融

NUS CPU 作业 `1176986`，同一构建的四项 Player150 观测与动作回归通过。在 D-204 wheel、12 个固定种子（804128–804139）的脚本对局中收集 T1–T14 的 1,530 个非单选决策状态，其中 T8+ 有 979 个。固定相同状态、卡槽顺序、掩码及 3286 权重，只改指定特征，比较掩码内首选动作。状态由脚本产生，固定输入变化率不能推断整局收益或战团库里的行为分布。

| 单独改动 | 全部 1,530 状态首选改变 | T8+ 979 状态首选改变 |
|---|---:|---:|
| 隐藏对手旧战团、当时等级和回合，保留英雄 | 48 | 39 |
| 隐藏全量下一战对象信息 | 61 | 51 |
| 隐藏己方部分成长、商店生命支付、部分附件信息 | 26 | 17 |
| 把剩余步数输入临时写成 150 | 0 | 0 |

采样时最多已使用 43 步，最后一行无法推断临近超时时模型是否会调整。己方缺失一行只模拟部分字段，没有模拟基础向量中的价格、刷新、动态牌文等其它近似。脚本和日志在 `artifacts/runs/nus-player150-io-audit-20261121-01/`。Windows 两份归档为 `live-player150-speed-20261121-02`、`-03` 的 `decisions-full.jsonl.gz`。

## 优先级判断

1. 允许策略观测是实机公开状态的子集。当前应优先可靠读取己方有效经济、成长和可触发的卡牌状态。对手详细阵容留可选通道，通过保留、屏蔽和模拟实机缺失的对照评估信息价值。早期不必追求制作全大厅侦察输入。
2. 优先评估放宽换位次数，并保留防重复消耗。改一个参数时固定 3286、规则版本、场地和种子。记录受限回合、最终站位、战斗收益、有效和无效换位。总步数、冻结和取消分开验证。
3. 对 150 步触顶局单列金币、待选和关键经营动作，并保留未筛选的独立样本。若研究实机时间，用各类动作及确认的实测时耗模拟后期，单独评价执行差距。每类已执行动作仍需要合法映射、同一动作语义与可审计的回执。
