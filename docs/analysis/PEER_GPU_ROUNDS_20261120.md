# 群友模型四轮三小时训练准备报告

## 调度与预算

四轮共享同一个训练种子，每轮申请普通 `gpu` 分区的三小时作业，双 H100-47 MIG、32 核、96 GiB。训练器最多运行 175 分钟，并检查本次分配结束前 240 秒的截止时间；当前在途批次完成后保存。三小时是每轮分配上限。四轮合计最多 12 小时双切片分配，另计评测和排队。每轮实际处理的批数和完整局数取决于节点及策略的行动长度。

每轮训练成功后释放双卡，单独申请普通 `gpu` 单切片、16 核、48 GiB、最多 55 分钟做固定评测。评测通过完整性检查后，下一轮恢复刚刚训练完成的同一代权重、Adam、调度器、RNG、累计决策与原始 KL 锚点。模型参数在评测期间固定。四次监测合计 2,048 对，终点新种子再测 512 对，合计最多申请 4 小时 35 分钟的单切片资源。最后在 `normal` CPU 分区测 128 对八席自主经营局。训练和评测之间有可能重新排队。

## 评测与判读

1. **训练进度。** R1 至 R4 使用相同的留出库、协议 `035d2eddcffa36e8092f0975863cf1da93789be7818db5ad14df16941c59bee6` 和 425410000 起的 512 个种子。每个种子对原版、该轮末代各打一局，各轮重新带原版作同设备对照。按累计决策数看平均名次、效用、前四、前二、冠军、T8/T10/T12/T14 总攻血 P50 与各自的到达样本数。T9→T12 的成长比较只取两臂都到达 T12 的配对局，报告 log(1+攻血) 增量之差及区间。到达率单列，避免淘汰较多的模型因为只剩强局而占优。局的种子相同，但两侧在选择不同的动作后，商店与战斗可以分化。
2. **终点独立验证。** 固定第四轮末代为终点。监测场上个别轮次的最高分不参与选择。此前仅登记的 428410000 起 512 个新种子在相同留出库比较终点与原版。这验证对新模拟局的泛化；对手来源的独立性由训练、留出原局隔离提供。
3. **八席自主经营。** 431410000 起 128 个种子，每个焦点座位 16 次。其余七席由四个群友原版和三个固定 3265 自主经营，双方共享真实商店池，位置相对焦点轮转。原版和候选配对，单独计算该环境的协议摘要。记录逐局终局名次和所有回合的攻血。本系列可以检验模拟环境中的整局实力；真实客户端胜率另待实机证据。
4. **晋级。** 独立快照场要求候选平均名次更低、终局效用和共同成长更高，三者配对 95% 区间均支持相应方向，且 T12 到达率降幅不超过 2 个百分点。八席自主场要求名次和成长的点估计均同向，并展示区间。固定监测用于解释进步发生在哪一轮。仅单训练种子提供的证据针对这一代权重，不能估计换训练种子的波动。[强化学习评估中的不确定性](https://arxiv.org/abs/2108.13264)

## 运行、恢复与证据

正式配置的每个 GPU 作业仅可落入普通 `gpu` 分区。提交器使用 Slurm `afterok` 串接，失败依赖自动取消。计算入口还会验证上一轮评测的报告摘要和配对局数、权重、完整 Trainer 与源码身份。合法棋力波动只记录；非法动作、引擎或注入异常、损坏的恢复代、缺失评测均阻断接力。错误现场保留，重试写入带新作业号的目录。正式配置与演练使用互不重叠的种子。提交器逐个封存作业编号；连接断开时先核对已登记编号和 `squeue`，避免重复提交。[Slurm 依赖语义](https://slurm.schedmd.com/sbatch.html)

在服务器冻结发布目录下可用 `python3 ops/peer_round_series.py preview artifacts/runs/<新目录>` 查看整条依赖。正式入口是将 `preview` 改为 `submit`。已完成轮次的进展可用 `python3 ops/peer_round_series.py progress artifacts/runs/<系列目录>` 查看。每个 `round-XX/train.json` 指向独立末代，每个 `monitor.json` 指向配对报告；最后一轮的 `adaptive.json` 指向含所有轮次曲线与两种终点报告的 `series-summary.json`。[提交入口](../../ops/peer_round_series.py) · [计算节点入口](../../workflows/peer_training_rounds.py)
