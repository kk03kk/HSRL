## 2. 为什么会这样

`tier_target` 的记账是"某回合 tier 达到目标就 +0.15"，**不要求板面跟着涨**。
而升本要花 9–11 金币、当回合板面必然下降；`board_target` 的当回合惩罚只有
`0.30 × 0.5 × ΔL`，抵不过 +0.15 的确定性收益。于是 200 轮 PPO 收敛到一个捷径：

> **把金币全砸在升级上，不买随从** —— tier 超额达标，板面塌，名次崩。

旁证：42 轮时（`gap-g23a`）G2 的 T12 板面还有 1098（与 base 持平），到 208 轮掉到 803。
**这是渐进退化的，不是一次性噪声**。同一模式也解释了 F1：它在 T5 就把 tier 冲到 3.83
而板面只有真人 0.565 倍。

## 3. 更根本的原因：名次信号已经饱和

`base` 在 7 个引擎 bot + 真人 p50 战团下 `mean_rank = 1.177`、`win = 0.854`。
**名次奖励已经没有梯度了**：赢不需要强阵容，所以"把板面做到真人的 0.22 倍"照样第一。
在这种情况下，任何可独立满足的过程奖励都会压过（已经饱和的）棋力信号。

所以正确的修法不是再加一条过程奖励，而是**先把奖励信号弄得有信息量**：
把对手换成真正强的战团，让"阵容弱"直接输。

## 4.5 一个必须写明的混淆项：`anchor-beta`

G2/G4/H1 用的是 **`anchor-beta 0.02`**（E 系列配方），而 B3/C1/D1/F4/G5 用的是
**`anchor-beta 0.1`**（它们从 `config/league-entry.json` 派生，那是 S1 原配方）。
anchor 是"每步把策略拉回 champion 的 KL 惩罚"，0.1 vs 0.02 是 5 倍的漂移空间。

后果：**上一节"tier-target 打穿"的结论与"anchor 太弱"这个因素混在一起**，不能单独归因。
证据是 B3（同样的强对手，无过程奖励，anchor 0.1）只出现 T14 −17% 的温和退化，
而同一时期 anchor 0.02 的 G2/H1 是 T14 −44%。所以更准确的说法是：

> 在 **anchor 0.02** 的设定下，`tier-target` 会被"只升本不买人"打穿；
> anchor 0.1 时这条捷径还成不成立，由 **G5**（anchor 0.1 + tier-target + 板面门控 0.9）
> 来单独回答。

这条也提醒后续实验：**比较不同臂时先确认 anchor-beta 一致**，否则结论会串味。

## 5. 教训（写进流程）
1. **任何"可独立满足"的过程奖励都要先想一遍最省力的作弊路径**；
   `tier_target` 的作弊路径就是"只升本"。
2. **加过程奖励前先确认主奖励没饱和**（`mean_rank ≈ 1` 就是饱和）。
3. 短窗口（≤50 轮）读数会**系统性偏乐观**：G2 在 42 轮时"机制对了、板面没坏"，
   到 208 轮才露出退化。**验收要跑满预算再看**。
