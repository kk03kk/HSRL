# 从初始引擎到 PPO

这份手册把 37.0.3 的实测流程拆成可重复的阶段。每一阶段登记源代码、引擎指纹、规则、数据或种子范围、依赖、作业号和产物摘要。阶段数据和结果见 [37.0.3 研究记录](reports/37.0.3.md)。

## 阶段与交接

| 阶段 | 做什么 | 交给下一阶段的证据 |
| --- | --- | --- |
| 1. 固定上游 | 记录仓库和提交。在 NUS 构建平台原生 wheel，检查加载路径和源码指纹 | 冻结检出、wheel SHA-256、依赖版本、构建与冒烟回执 |
| 2. 验收游戏规则 | 同时验证卡表、热修、实机可见回执、完整对局、合法动作和异常快照。确认单线程和批量接口一致 | 共享训练规则和可重放的卡局回归，版本独立的模拟器验收报告 |
| 3. 策略教师 | 原版 Bot 留作对照。把攻略拆为核心、启动、经济、兑现与成型。用原版大厅、专题种族和完整大厅配对测试 | 冻结教师、逐流派数据、代表棋盘、稳定的原版和混合大厅 |
| 4. BC | 从教师完整局采自然数据，沿学生运营收集纠错。按整局分好训练、开发与独立种子。开发实战和离线指标一起选模 | 18M 模型、卡表与观测契约、独立准入报告、冻结初始化文件 |
| 5. PPO 预跑 | 核对当前策略采样、价值与奖励、Adam 恢复、同权重概率、BF16 形状、显存和吞吐 | 已验证的训练配方、可恢复断点和基线面板 |
| 6. 脚本场 PPO | 训练过程保存逐轮记录。在开发面板选一份检查点，由独立对局给晋级结论 | 有样本和置信区间的新基线，逐动作、升本和成型审计 |
| 7. 战团库与短对照 | 比较连续模拟供体和真人盘面，校准回合压力。验证牌池、抽样和自然结束。隔离对手环境与超参数两类变量 | 来源隔离的库、配对结果、保守正式配方和降级方案 |
| 8. 分段放量 | 同一初始权重准备对照，按预设门槛决定保持、提高压力或回退。终点先封存候选，再测独立组 | 全部阶段选择、最终检查点、配对报告和模型晋级结论 |

## 本轮规则和决策

- [模拟器验收](SIMULATOR.md)锁定 37.0.3、八席、十族抽五，禁主动换位和取消。入场位置仍是合法决策。每回合 100 次操作，耗尽时先完成待选，再强制结束。两个预算字段进入模型观测。
- [策略教师](STRATEGY.md)兼顾通用运营和全部攻略路线，验收分别统计发现核心、机制启动和终盘成型。教师采用合法入场位置写站位，保留可根据发牌和当前资源转型的逻辑。
- [BC 准入](BC.md)在两个大厅分别按 8,192 个新整局种子配对。平均名次差的 95% 区间上界不能超过 +0.15，前四率差的下界不能低于 −3 个百分点。动作 Top‑1 与对应流派覆盖用于诊断。
- [PPO](PPO.md)用当前策略的完整轨迹做更新，BC 初始化和 Adam 续训来源各自登记。终局名次从第一到第八映射为 `[1, 0.3, 0, −0.05, −0.1, −0.15, −0.2, −0.25]`。开发面板负责选择，留出面板负责最后判断。
- [战团库](WARBAND.md)保留真实盘面上的卡、属性和回合。真人原局或模拟生成种子划分隔离。注入缺少真实对手的同步招募和完整牌池竞争，留存动态脚本场用于保护能力。最后可用回合覆盖不足时交还脚本继续经营。

## 从踩坑中得到的检查方法

| 曾经的问题 | 现在怎么查 |
| --- | --- |
| 模拟器的补丁和客户端 build 容易混淆 | 同时记录客户端卡表、服务器热修、卡表摘要和实际加载 wheel。真实日志按可见回执验证确定性字段 |
| 收费饰品被嵌套发现遮住后出现空合法掩码 | 保留原失败种子和待选栈状态，回归用例覆盖下层菜单不可支付的情况 |
| 只看模仿准确率，忽略模型进入自己造成的陌生状态 | 增加学生控制下的纠错轨迹，再用完整对局挑 BC 候选 |
| PPO 同权重采样与回放不一致 | 从故障断点用相同批形状重跑，再做 FP32 对照。采样、回放和梯度前向统一固定形状，继续核查 KL 与回放保护 |
| 合法动作中的冻解空转 | 完整重放后比较同一商店实体和冻结标志，再统计下一轮买入保留牌。原始动作 ID 和实际操作证据一起保存 |
| 战团席菜单阻塞或尾段反复打平 | 后战斗待选归还池副本，同回合独立供体去重。覆盖不够时恢复原生脚本 |
| 短训开发提分却未独立复现 | 划分训练、开发与独立种子，用同预算对照和配对区间。先做小实验，再把稳定收益用于生产配方 |

## 新补丁怎么接入

1. 在独立目录或 worktree 获取新上游提交。先保留旧运行所需的源码、wheel、种子、权重和报告。源码历史可用版本标签复现，冻结作业继续使用自己的检出。
2. 按新卡表、补丁和实机日志重新验收引擎，检查动作编号、观测语义、预算、菜单、卡牌上下文及超长战斗。通过完整对局后再接训练。
3. 迁移教师框架、攻略、站位和验收代码，重新核对当前流派核心、合法位置、饰品和种族。留一份新补丁的原版对照。
4. 重建或验证示范、纠错与战团数据。即使维度相同也逐项校验卡 ID、观测、动作和终局效用。旧权重若迁移，用回放与新补丁独立面板验证。
5. 复跑 BC 准入与 PPO 预跑，确认恢复、精度和吞吐后再分段继续训练。新补丁的对照和指标单独登记，保留足够未用数据做最终晋级。

具体脚本与文件位置见 [项目文件框架](PROJECT_LAYOUT.md) 和 [文档索引](README.md)。
