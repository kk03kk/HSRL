# HSRL 模拟器基线

- 基础客户端卡表为 37.0.2.256589，运行服务器规则为 [37.0.3 热修](https://us.forums.blizzard.com/en/hearthstone/t/3703-hotfix-patch/168317)。
- Rust 引擎、卡表和引擎测试从 HSAI 的 `46331a062332fafc6ee93ac6664fc1209e82a484` 导入，核心树为 `40d277a26eb607e1142d75257f25a3d3b2165a68`，与 HSAI 37.0.3 冻结发布 `ebc9774` 的引擎相同。HSRL 沿用 TavernGym 的 crate 和 Python 包名，保留上游许可。
- 冻结的 37.0.2 工作区可从 Git 标签 `hsrl/37.0.2-bootstrap` 找到。37.0.3 保留 3,983 张有序卡 ID，共 32 张卡的内容或候选配置发生变化。卡表已经入库，构建、对局和验收均使用它。卡表生成器在上游资源与 37.0.2 补丁表生成的规范内容上应用 37.0.3 增量。

## 训练动作和观测

策略、采样和训练共同使用 Rust `RulesConfig::hsrl()`，Python 对应 `taverngym.hsrl_config_json()`。默认八席、十族随机抽五族。合法掩码与执行路径统一拒绝主动换位和取消。随从上场位置和冻结保留。每席每招募回合 100 次操作，达预算后只允许完成已有的待选，菜单清空后只允许结束回合。非法动作不计预算。上游默认配置仍可用于历史基准和规则对照。

动作编号保留 245 项，观测为 3,229 个浮点和 124 个卡槽。最后两个浮点依次是已执行动作数除以预算，以及剩余动作数除以预算。预算耗尽后剩余始终为零。校验动作、卡表和观测语义后再决定旧资产的兼容性。

## 复现

- 从已提交的冻结检出，在 Slurm 登录节点准备独立输出目录，用 [构建入口](../deploy/slurm/bootstrap.sh) 验收 Linux wheel、Python 测试和 16 局八人对局。
- 用 [模拟器验收入口](../deploy/slurm/validate_simulator.sh) 运行 Rust 全量测试、8,192 局原版 Bot 和 512 局含一个随机合法动作座位的对局。作业失败时在输出目录保存异常种子、回合、原因和状态，失败局不能作为名次样本。
- 历史卡局的回归保留种子 6200549 和实际四张候选饰品。测试构造发现结束后露出下层付费菜单的状态，核对买不起的旧菜单正常退出、金币与已持有饰品保留。
- [实机经济夹具](../crates/taverngym/tests/fixtures/live_3703_economy.json) 来自 11 月 22 日热修窗口内的单人 `Power.log`，取首次完整的买入、升本、冻结、卖出、刷新回执。夹具仅保留金币、酒馆等级、可见牌区变化和源文件摘要。原始日志中的客户端 build 为 255790。37.0.3 是服务器热修，客户端 build 与热修版本分别登记。该验证覆盖有完整回执的普通操作，真实随机序列、隐藏状态和罕见卡牌联动仍需相应证据。
- 11 月 24 日另一份 [实机热修夹具](../crates/taverngym/tests/fixtures/live_3703_hotfix.json) 记录普通尖利的鲨鱼的酒馆等级标签为 5、Training Certificate 的费用标签为 5。Python 测试直接对比已加载 wheel 的卡表，两项都是本次热修改动。
