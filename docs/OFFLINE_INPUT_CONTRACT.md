# 玩家观测与客户端离线桥契约

当前默认训练模型为前馈Entity Transformer；下文记忆提交条款也覆盖历史循环模型。此文描述离线接口，不表示已完成实机接入。

当前训练输入：3,227 floats、124 card IDs、245 位合法 mask，以及8维扩展效果 token。该版本是36.6.3无纳迦实现基线，不是完整37.x实机。

PublicHistory 已实现从完整起点和明确回执重建 actions_this_turn/freezes_this_turn，并支持带来源的公开计数更新。未完整观测或有gap时为未知；上场事件不能单独推算Brann/附件等影响后的战吼次数。该结果可供上下文构建器使用，不能替代尚未齐备的其他输入。

## 四个接口

- ClientSnapshot：旧系统序列化观测，必须有 game_id、非负整数 revision、build；保留 phase、ready、实体和交互请求。stamp 排除捕获时间，绑定其余语义上下文。
- PolicyInput：features/cards/mask/extras，附来源登记。encode_snapshot 检查身份、版本白名单、字段形状、有限数值、词表、基础字段相符、预算token；不从随机 Game 重建未知状态。
- ActionIntent：唯一 intent_id、game_id、revision、stamp、flat action、无损语义及实体/选择请求绑定。每次从当帧绑定产生，不能复用过期索引。
- ExecutionReceipt：intent/game身份、before/after revision、applied/rejected/not_sent/waiting/unknown。只有明确 applied 且新 revision 才提交 GRU 和有效计数；重复回执幂等，未知结果保持待决，拒绝不推进记忆。新局重置，按原模型 memory_horizon 周期重置。

## 逐组字段来源

| 输入组 | 可从客户端直接取得 | 需要历史确定重建/补充 | 当前准入 |
|---|---|---|---|
| global（53） | 回合、生命护甲、金币、本数、升本费、场/手数量 | 下回合金币、累计宝石/法术/酒馆增益、免费刷新、技能次数、附加效果、畸变祭品等 | 完整块必需；turn/gold/tier/upgrade 与原始字段交叉校验 |
| quests（6） | 可见任务和目标 | 任务进度/目标精确语义 | 必须明确，不能将未知任务视为无任务 |
| pending（9） | 交互请求与选项 | 原生 pending 枚举、源卡与目标顺序 | 不支持的多段/多选明确阻断 |
| board（217） | 卡ID、攻血、星级、金色、关键词 | 附着数量、护盾次数、动态种族 | 与当前原生编码同口径 |
| hand（400） | 可见手牌、费用、实体顺序 | 暂时/战斗限定/锁定/保留等标志 | 不默认隐藏标志为0 |
| shop（320） | 可见商品、价格、位置 | 单牌冻结/保留/标记等状态 | 资源费和卡面COST不能混同 |
| choices（640） | 选择实体、展示顺序 | 目标/发现/饰品不同状态语义 | 选择request ID和对应实体必须绑定 |
| opponents（剩余1582） | 公开计分板、可见英雄/饰品等 | 本玩家实际见过的战团与回合 | 不允许当前真实隐藏战团补齐；包含其余固定状态编码，细节以obs.rs为准 |
| cards（124） | 当前可见卡ID及已见历史 | 固定槽位、黄金/运行时副本到静态词表映射 | 未知卡拒收，空槽明确用空ID |
| extras（变长） | 部分可见计数器、附魔 | actions/freezes、战吼次数、counter/gift/shield/gems、临时增益、激活次数、附件、额外亡语、effects/counters/levels、技能本回合使用等 | 缺任一需要值不得猜测；需历史来源或直接证据 |
| mask（245） | 服务端Options和当前控件 | 语义动作→原生flat索引、目标和放置位置 | 不拿旧模型候选数组当新mask |

`blocks()` 按原生layout计算块宽度；这里的 opponents 是“尾部剩余编码块”的工具名称，并非其中每个维度都只表示对手。卡槽包含英雄/技能/神灵/任务奖励/秘密/战团/手牌/商店/选项/饰品及对手已见历史，不能只按三种区域串接。

## public-context.v1

在旧 JSON 中新增独立 policy_context：format、identity（完整实验身份）、features（上述命名块）、cards（124个静态字符串ID，空槽空字符串）、extras（[cardID,owner,8维值]）、mask、provenance。每块来源必须是 client 或 history；native_fixture 只在显式夹具模式接受。

这是一个**完整编码上下文的输入协议**，不是自动证明字段真实的认证机制。调用方必须按上表从客户端/历史建立该上下文；本轮未把旧系统缺失字段自动重建完成。当前真实历史样例应被拒收，不能改来源标签就宣称实机适配完成。原生投影与其自身tensor逐值相等，只证明编码传输和词表转换，不是独立客户端特征编码器的等价证明。

## 动作与执行边界

actions.py 覆盖245编码。client_actions.translate 支持明确的一步买/卖/刷新/冻结/升本/结束、技能、激活、选择/目标、上场/磁力及单次移动重排；一基客户端放置位置转换为零基。目标不存在、复杂多选/多阶段、来源不明或顺序不能无损表达时，返回不支持原因，绝不自动换成其他动作。

dark_gift 需明确scope；两个英雄技能需可见controls确定槽位。原生 Cancel 不等于一切客户端取消流程。对角 Move 不改变站位，不强行生成旧客户端无意义重排。完整原生mask和真实可表达动作仍须在接入时核对，不能以删除难动作隐藏适配缺口。

## 验证界限

已验证：原生公开投影张量相等、模型推理/意图/模拟回执、旧真实JSON解析与明确缺口、动作语义翻译及错误分支。尚未验证：完整真实客户端→原生特征独立编码、全类型实机动作、真实延迟和完整实机对局。本轮不会导入旧工程驱动，也不会修改旧工程。
