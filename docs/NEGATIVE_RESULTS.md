## A. 奖励方向

| 方向 | 结论 | 证据 / 判词 | 何时可以重试 |
|---|---|---|---|
| **阵容覆盖奖励（comp-target）** | **否** | 用户判词：模型"买完随从不上来、买完核心卡就不玩了"，来吃这个奖励。实验臂 H1 全 FAIL | 只有当"买了必须上场"成为硬约束时 |
| **retained_growth 保留成长塑形** | **否** | 用户明确否决："这个是你自己乱想的" | 不重试 |
| **无板面门控的 tier-target** | **否** | 被打穿：模型把金币全砸升级、不买随从，板面 −33%、覆盖 −70%（`REWARD_GAMING_20261113`） | 已有门控版本在跑，不要再做无门控版 |
| **只改奖励、不改对手场** | **否** | D-052/D-054：名次奖励在模型所处板面区间不敏感；多轮奖励实验都没超过"换对手场"的效果 | 对手场已换成校准库后，可另行评估单个奖励项 |
| **用"升本节奏奖励"逼模型升本**（带板面门控的 tier-target） | **否（2026-11-14 实测）** | 第一轮 303 轮训练后，候选平均 tier 比冠军**低 0.47~0.74**（T8–T18），而中位板面高 1%~16%、名次显著更好（−0.27）。**奖励没把 tier 拉上去；而且 tier 更低反而更强** | 若仍想升 tier，必须先证明"同板面下更高 tier 更好"；不要再用奖励硬拉 |
| **在 bot 场用名次当训练信号** | **否** | bot 场 `mean_rank` 已饱和到 1.177（胜率 0.854），没有梯度 | 不重试；用校准真人场 |
| **法术槽强制补贴（forced_spell）** | **否** | `legal_decisions=0 / blocked=2137`：设计前提（法术槽恒合法）不成立 | 引擎行为改变后才谈 |

## D. 不是"方向"，而是踩过的坑（写死，别再犯）

| 坑 | 事实 |
|---|---|
| 分段续训会破坏 anchor 保护期 | `i = trainer.updates`（优化步数），第二段的 β=0.1 直接失效 |
| `--trainer-state` 会覆盖 `--lr` | 用 state 里的 `base_lrs`；想要论文的 6e-06 就不能带它 |
| 这个训练器没有 `--resume` | 续训参数是 `--trainer-state` |
| Slurm 的 `AllocTRES` 说两张卡 ≠ 进程真能用两张 | `h100-47` 是 MIG 切片，可能落在同一张物理卡；必须查 `device_count()` |
| "配置的 coef" ≠ "实际付出的量级" | 必须从 collect stats 反算（D-053） |
| "没掉血" ≠ "赢了" | 战斗归因必须用引擎的 `won_last/lost_last`（D-055） |
| 只加 tier 奖励不看板面 | 会被"只升本不买人"打穿，必须带板面门控 |

## 怎么往这张表里加条目

1. 在 `docs/DECISIONS.md` 追加一条 `D-###`，写清**判负的证据**（不是"感觉不行"）；
2. 在本表对应分区加一行，**必须填"何时可以重试"**（填不出来说明还没想清楚为什么失败）；
3. 不要删旧条目——判负结论也会被后来的证据修正，那时加一行"修正"，不覆盖原文。
