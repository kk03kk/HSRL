## 执行顺序与验收条件

### P0：验收当前服务器链，保留可复现基线

现在进行。读取 qualification 日志与进度，确认 40 波自然完整结束、无拒绝/无名次终局；确认 train 状态、实际设备、源码身份和输出目录。留存日志、配置、身份、种子、BC anchor、checkpoint 及失败快照。优先取回轻量指标和日志，模型按需要再传。

不对正在执行的源码、原生扩展和配置热修改。若资格失败，afterok 应阻断长训练，按实际失败快照修复再验收；若通过则允许既定长训练开始，不重复提交。

验收：作业状态和源码/模型身份可追溯，能区分稳定性、吞吐与棋力。正式训练出现持续退化或相对 BC 没有提升时及时评估剩余算力用途，不默认必须跑完 1000 波；不在没有新证据时擅自取消当前作业。

### P1：回放与诊断，先让模型行为可审查

本地立即可做，不依赖长训练完成。

实现我们自己的版本化轨迹格式、单局导出和本地只读查看器，展示回合、前后局面、动作/动作组、合法动作、策略 top-k、名次、实际 applied、记忆重置位置。调试全局状态和策略可见输入分开标识。适配 BC/native bot/PPO；先能用本地小规模模型与已保存状态演示，再接入服务器 checkpoint。

新增统计：每局和每回合有效决策数、EndTurn/买卖/刷新/升本比例、重复无进展操作、策略熵、截断/异常数量、采样与更新耗时。分阶段统计，不把正常结束回合直接当错误。

验收：同一记录可重放并对照原动作，等待/延期不计为执行，缺字段明确显示未知而非填造；你能通过几局回放指出具体失误。性能计时不改变训练采样、RNG 或学习目标。

朋友回放和质量统计是参考来源；实现落本项目，复制具体代码前核清对应授权。当前服务器代码不支持的新遥测，在下一发布版开启，不能宣称旧日志包含这些字段。

### P2：高影响规则与实机接口差异清单

与 P1 同期启动资料和源码核查；修复按证据分批实施。完整版本迁移不是第一次就要全量完成的前提，但扩大训练前必须明确训练分布。

优先级：经济/刷新/升本/三连与公共卡池 → 战斗伤害、先攻与配对/鬼魂 → 高频召唤、亡语、复仇、圣盾等事件时序 → 英雄/饰品/任务等跨回合效果。按影响频率、收益敏感性和已知反例排具体工单，不因为朋友代码不同就认定我们错。

每项记录目标版本、当前实现、官方补丁/客户端数据、用户规则确认、最小局面、预期结果、测试和未决假设。精确同血同时出局等未知项保留明确假设。纳迦继续排除；36.6.3 基线不能标为完整当前版本。

同时只读核查 `D:\HearthstoneAI`：它能读到哪些字段、卡牌/实体 ID、待选项/目标选择、交互动作和阶段边界。提前识别训练输入中真实客户端拿不到的字段，制定历史重建或缺失值协议。旧系统暂不修改。

验收：有一份可执行的版本/卡牌支持清单和优先差异台账；每个确定高影响缺陷有最小回归；新增观测能由客户端或合法历史重建。规则变更生成新身份、新 run；只做兼容权重初始化，不混用旧 rollout 或绕过 resume 校验。

### P3：独立评测，回答 PPO 是否实际超过 BC

P0 有可用 checkpoint 后开展；P1 的回放帮助解释结果。

用统一固定对手、随机种子和席位协议比较 native bot、BC anchor、PPO latest/best，区分 learner greedy/sample。保留现有 validation 选优，另用未参与选优的 test seeds 做确认。统计平均名次、前四/吃鸡、完整局数、截断率及按大厅计算的不确定性；不把同一大厅多个席位或动作当独立对局。

先用小批量发现问题，正式候选再按置信区间精度扩大到数百局，仍不明确再增加；多训练 seed 在方案值得投入后补，不一开始无差别跑很多实验。不能凭单局回放或几局均名次决定优劣。

验收：能独立复核选优协议和 test 结果；明确结论属于“稳定但没进步”“提升有证据”或“样本不足”。模拟器规则身份变了，旧/新环境分别报告，不能拼接为一条提升曲线。

### P4：按诊断提升学习效率和棋力

P2 的阻塞规则/观测差异解决、P3 的瓶颈明确后执行。一次主要改变一个因素，保存固定对照。

若策略空过/乱刷新：先查输入、动作标签和采集，再调整 BC 数据质量、动作分布与采样。若中长期规划差：比较记忆跨度、序列训练和价值预测，不立即堆模型。若学习稳定但受弱教师限制：利用你的局面批注构建高价值决策集，包含玩家可见历史、合法动作、推荐动作/可接受集合和理由，再研究整局专家轨迹。若吞吐不足：按实际采样/前缀/反向/评测耗时调 CPU、batch 与推理，不先上多节点。

不默认引入密集奖励；若确需辅助目标，明确是否改变最终名次目标并做消融。不能只用“训练 loss 降低”作为成功指标。

验收：每项变化有可靠对照、资源成本和独立评测结果；确认改进可复现后才增大训练预算。目标是提高强度和数据效率，不是增加功能数量。

### P5：纯观测搜索的小规模 A/B

非主线前置条件。P2 信息边界可信、P3 已有可用叶评估器后再启动。

先测试局部站位或受限招募候选，再决定是否做完整 PIMC＋PUCT。隐藏世界从玩家信息重建；不复用真实对手秘密状态。不变量失败拒收，oracle/BotPrior 数据与正式数据强制隔离。修正朋友代码中损失 mask、零温度平局、无效世界准入等问题；搜索分支正确复制/推进 GRU，不能污染真实策略记忆。

验收：相同对手和种子下，search-on 相对 search-off 有可测收益，包含计算成本、截断和单次延迟；符合实机回合时间预算。无收益就停止，不因已经写了搜索而强行进入主线。收益成立后才研究搜索标签蒸馏。

### P6：实机适配与分阶段闭环

P2 先做接口核查；正式接入不必等待搜索，只需当前可用模型和可信观测/规则边界。

新适配层落在主项目：客户端状态→版本化策略观测→合法动作→语义操作→执行回执。协议覆盖英雄/待选项/指向目标/买卖/上场/磁力/站位/结束回合，定义实体消失、状态变化和动作重试的处理。实机按实际成功操作推进记忆；超时导致的回合结束同样要同步阶段，不能套用模拟器无限决策速度。

先离线客户端日志回放核对观测与动作映射，再影子模式只给建议，之后受控单步执行，最后完整对局。将状态识别、动作执行、模型决策三类问题分开计数。训练与实机一致性不足时先限制支持范围，不能把默认值伪装成真实字段。

验收：离线映射正确、推理延迟满足预算、动作执行可确认、异常有恢复与终止路径；在明确版本和支持范围下连续完成真实对局，再讨论高强度达标。实机胜负是最终证据，模拟器 bot 成绩不是替代品。
