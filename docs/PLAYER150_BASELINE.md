## 模块 1 · 模拟器与卡牌规则

Rust 引擎是训练环境的规则权威。固定有序卡表承载卡牌身份、基础属性与候选池。招募、战斗、触发、目标及动作合法性由 Rust 实现。Python 调用原生观察、合法掩码与步进接口。实机的动作授权由客户端提供，卡牌规则版本负责保持动作语义一致。

D-204 沿用 37.0.2.256589 基础卡表与 37.0.3 服务端规则，修正等量战团的随机先手、Talent Scout 上场条件、副厨贴纸与吞噬之爪交互。通过 948 项 Rust、1,180 项 Python、6,845 帧真人战团和 8 局、2,624 决策、一次 PPO 更新的训练入口检查。后续升级以确认的规则差异或正式补丁为起点。新构建需要独立版本锁、同版本回放、回归与训练接入证据。极罕见的卡牌交互、隐藏状态和实机计时仍待确认。[完整验收](analysis/SIMULATOR_PARITY_QUALIFICATION_20261121.md)

## 模块 2 · 观测、动作与模型

| 项目 | 3286 冻结实现 |

| 观测 | `hsai.player150/v1`，4,967 浮点和 124 卡槽。固定己方状态、卡牌顺序与语义、回合预算、公开大厅信息。训练输入的下一战档案包含历史战团与回合。当前实机通常只有公开的下一战身份，旧战团缺失。编码的缺失路径及已知近似继续按 3286 复现。 |
| 动作 | 245 个原生动作，槽号和语义固定。训练掩码由 Rust 合法性和 Player150 护栏组成。实机以当前 Options / EntityChoices 映射候选，应用同族护栏，再按状态、提交和回执确认。英雄选择、发现、二选一、目标与磁力保留各自的绑定。 |
| Player150 预算 | 招募每回合最多 150 个主动动作，场上独立换位最多 3 次，冻结与解冻共 2 次，取消禁用，`sims=0`。训练超限由引擎处理待选，实机超限停手等待客户端。 |
| 核对结果 | 本轮使用实际 Windows 发布离线重放两份 3286 归档，44 + 97 个决策的动作、观测 SHA-256 和掩码 SHA-256 全部相同。 |

合理的长期实现以己方资源、牌区、真实价格、增长进度、分支效果和可靠授权为核心。当前观测里的传值近似有独立审计。战团库的活对手按回合重抽，下一战身份、历史阵容和全大厅情报的价值属于独立课题。维持 3286 原输入与动作语义。实体级防循环、操作时间成本、换位和冻结剩余次数，以及观测精简，继续保留为候选研究。样本已证实循环存在，消除循环的固定权重试验尚未确认跨场棋力收益。[观测差异](analysis/PLAYER150_OBSERVATION_REVIEW_20261121.md) · [换位与冻结](analysis/PLAYER150_MOVE_FREEZE_AUDIT_20261121.md)
