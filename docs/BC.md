## 首轮 BC 配方

18,147,729 个可训练参数。实体 Transformer 宽 384、8 层、8 头、前馈宽 1,664。输入包括 3,229 个浮点特征、124 个卡牌槽与 245 项合法动作掩码。使用 HSRL 当前引擎生成的卡表与观测。训练从随机权重开始，使用本轮新采数据。

首轮预设是单张 H100 MIG 47 GB，BF16 混合精度，AdamW，学习率 `3e-4`，批大小 768，最多 3 个 epoch，训练种子 71427。动作模仿为主，名次交叉熵和价值回归各乘 0.05。价值按实际第一至第八名映射为 `[1, 0.3, 0, -0.05, -0.1, -0.15, -0.2, -0.25]`。两类大厅按游戏平衡。动作模仿只训练有多个合法选项的行，第 8 回合起动作损失样本权重为 1.35。开发轨迹计算离线指标，每个 epoch 分别在每类大厅运行 256 局，先按两场平均名次、再按离线动作交叉熵选模。

选定后按原版场和混合场各跑 8,192 个独立种子，对照同种子、同座位和同大厅的教师。两类大厅均要求平均名次差（BC 减教师）的配对 95% 区间上界 ≤ +0.15，且前四率差的下界 ≥ −3 个百分点。报告前二、吃鸡、终局效用、回合升本和战团攻血、动作预算用尽比例。对局出现非法动作或无法得到有效终局时，评测报错并留种子诊断。PPO 准入独立于对少数流派掌握程度的专项检查。

## 可复现入口与验收记录

冻结运行目录是 `~/projects/HSRL/artifacts/bc/37.0.3-69011f7d5c74`。其中 `jobs.txt` 记录作业，`native/wheels.sha256` 和 `env/requirements.freeze` 记录 wheel 和 Python 环境，`preparation.json` 记录源码、指纹和数据验收。37.0.3 原生扩展指纹为 `9432249ae4888d0f`。旧项目只用于参考与源码迁移，运行用 HSRL 自己的冻结检出、依赖、wheel 和数据。

先用 [Slurm 入口](../deploy/slurm/bc.sh) 提交 `native` 和 `env`，两者完成后跑 `install-model-wheel`。按 `bc_splits.tsv` 对各 split 跑 `collect`，原生采集器生成逐局索引和轨迹，再由 `tools/bc_prepare_data.py` 审计和封存。CPU 运行 `preflight RUN cpu`，GPU 用 `tools/bc_preflight.py` 读取两个试采集，参数 `--device cuda --batch 768 --out RUN/preflight-cuda-full.json`。最后从计划训练的冻结检出运行 `tools/bc_ready.py RUN --parity PATH`。本轮的 `PATH` 使用既有策略开发集的逐局表 `artifacts/strategy/37.0.3-6340a5524871/dev/pairs.csv`。

本轮 128 个原版场试采种子的座位和名次与原策略评测逐局相同。前向、反向、合法动作屏蔽和奖励映射已测。NUS H100 上实测 768 行，PyTorch 记录的前向和反向 CUDA 分配峰值为 4.77 GiB。空优化器检查点已重载并核对输出，随机初始化模型走完 8 个配对完整局。48 项 Python 测试通过。累计优化器更新 0 次，带真实 AdamW 状态的中断续训对照留在训练阶段最先验证。GPU 冒烟作业 1204899，批量数据作业 1204847，Python 测试作业 1204879。

用户确认开始 BC 后，从 `preparation.json` 指向的冻结检出提交单卡作业。入口依次为 `bc.sh train RUN`、`bc.sh resume RUN`、`bc.sh evaluate RUN RUN/train/best.pt EVAL_OUT`，其中 `EVAL_OUT` 为新的独立评测目录。阶段入口校验冻结提交与已安装的原生扩展。训练按块保存 `latest.pt`，保存内容含模型、优化器、随机数状态和进度；恢复必须使用同一运行目录与配置。首次训练可先执行少量块并比对同配置续训的检查点，再用完整预算。

## 正式训练中的效率检查

- 保留了每轮权重。基础训练共 3 轮、10,143 次更新。第 3 轮开发集的动作 Top‑1 为 89.54%，高于第 2 轮的 88.36%。在每场 2,048 局的开发实战上，第 3 轮原版场吃鸡率比教师低 9.52 个百分点。开发选型使用两场各自的配对名次和前四率相对准入门槛的最弱一项。
- 第一轮开发实战识别出分布偏移后，在基础训练继续时提前采集纠错数据。每场 1,536 局，受训模型行动，教师提供标签。教师动作以 10% 的概率实际执行。共采集 551,960 条可选动作，107,323 条师生分歧。逐行检查掩码、名次、卡表和分歧标记。以基础第 2 轮为起点，使用自然数据和纠错数据微调 2 轮，学习率 `6e-5`，分歧附加权重 0.75，第 8 回合以后附加权重 0.50。微调共 8,380 次更新。数据与优化参数同时变化，实验衡量整套流程的效果。
- 在基础训练中实测了 18 步、恢复再跑 18 步与连续 36 步的一致性，模型、AdamW、步进和随机数状态相同。基础作业 18 分 27 秒，包含这项对照和三个小开发面板。微调作业 16 分 24 秒。微调每 36 块保存一次恢复点，基础训练每 12 块保存。
- 同一模型、同一 768 局，在 H100 MIG 上并发 192 时为 44.14 局/秒，并发 384 时为 66.61 局/秒。两种设置逐局结果完全相同。独立评测固定设备与并发，并把两个大厅拆成可单独重试的作业。一个原本申请 MIG 的任务实际加载了整卡，在推理前被设备检查拒绝，换到已验证节点后跑同一批种子。单独的整卡更新探针在 xgpi0 遇到非有限梯度，xgpi1 同批更新通过。跨规格逐步位级一致性仍需重新验证。
- 旧项目第 99 轮的实际失败快照包含买不起的下层付费饰品菜单。本轮在 37.0.3 原生引擎重跑对应回归并通过。旧 PPO 同等轨迹的 KL 探针每四步检查保留整轮复算，更新由 28.12 秒降至 22.13 秒。这是后续对照的起点，实际 PPO 采样、更新、整卡吞吐和随机种子覆盖要在 37.0.3 重测。
