## 本地核对结果

- 新布局与旧NUS布局分别为engine/workflows/config/artifacts和rust/scripts/personal。只读采集命令按实际旧NUS布局，不上传HSAI代码覆盖运行目录。
- 正式入口从冻结4159完整Trainer开始，累计基线198819917。新训练量必须扣除继承量；4159→更大版本不是Adam步数证明。
- 申请24h；控制器1410分钟包含45分钟终评预留。有效训练窗口少于24h，不能将采集与PPO重叠时间相加当墙钟。
- 512局/8actor，BF16，单epoch、minibatch1024；80总动作/5换位/重复去抖2，严格镜像。真实参数须以本次plan、config和history内实际LR为准。
- 起点及每30M决策中途评测为12种子×8学习席位=96局，不是96个独立训练seed；终评64×8=512局。重复使用固定Dev种子可观察趋势，不能证明对未见环境泛化。
- `status`/`training-report`/`learning-health`由分段退出后的控制器刷新，不是秒级心跳。卡顿要结合history与latest新鲜度、评测文件/日志和Slurm状态判断。
- 当前经营统计阶段为before_end_turn，库捕获在EOT效果结算后，不能将两者牌面均值直接当同一时点。后期统计要同时看存活到达率，否则只比较幸存者会误判。
- 已有`report_personal_run --last`会先读整份history，不用于受限登录节点；`report_firestone_learning`需要完整收尾report和大原始评测，也不直接用于在训登录节点。

## 本次采集范围与限制

`tools/nus_readonly_health.py`仅用标准库，不导入训练包。单JSON最多2MiB；history≤16MiB时全读，否则首/中/尾各4MiB，只报告抽样窗口统计，不冒充全程累计；日志只读尾部24KiB左右。没有加载/哈希大模型，没有扫描战团帧，没有查询封存Test评测。Test仅读取manifest元数据。

运行中的JSONL末行可能尚未写完，正常忽略；latest在前后两次读取间可能更新，不能据此判坏。缓存汇总可能滞后，须与其修改时间一起解读。只读stat不等于验证当前checkpoint张量或Adam/RNG的内容。

## 判定原则

| 类别 | 需观察的实际证据 | 处理原则 |
|---|---|---|
| 工程失效 | 非有限损失/梯度、非法动作、截断、活席注入缺失/拒绝/回退、卡池异常、checkpoint错误 | 优先保存最后有效提交点与现场；不让异常数据继续更新 |
| 学习空转 | 连续零Adam更新、处理率长期明显下降、KL与流水线回退频繁 | 核对近期窗口及完整分段；不是仅看采样dec/s |
| 真正停滞 | 非评测阶段history/latest长期不动，日志无进展，进程/Slurm证据一致 | 再按具体阶段诊断；不凭status旧就停止 |
| 策略崩塌风险 | 多个评测点持续大幅恶化，动作/花钱/升本/到达率与熵等多证据同时恶化 | 人工判断适应期还是无效学习；不用单次96局或单个阈值硬停 |
| 正常波动 | 有效更新与数据质量正常，短期分数升降或CI不显著 | 继续学习并记录，不重置9小时成果 |
| 过拟合 | 固定Dev改善并不能证明未过拟合；需后续独立协议或封存Test | 本轮不额外启动昂贵测试，不查Test对局结果 |
