# 阵容覆盖奖励（comp-target）：把「33 个流派的核心卡」写进 reward

状态：**已实现并单测（2026-11-12），首个实验 H1 待启动**
入口：`hsbg/az/train/comp_target.py`、`tests/test_comp_target.py`、
`config/league-entry-h1.json`

## 1. 为什么需要第三个奖励

2026-11-12 的两条证据把问题定位得很干脆：

1. **升本节奏修好以后，板面还是不动**（`docs/analysis/TIER_TEMPO_20261112.md` §7）：
   G2 在 T12 的平均 tier 已经追平真人（5.83 vs 5.78，base 5.35），但同回合板面
   只有真人的 **0.22 倍**（1098 vs 4983）。
2. **阵容覆盖差一个数量级**（`tools/analyze_composition_coverage.py`）：

   | side | ≥1 张 S 核心卡 | ≥2 张核心卡 | ≥3 张核心卡 |
   |---|---:|---:|---:|
   | 真人吃鸡局（968 局） | 0.604 | 0.438 | 0.111 |
   | base | 0.229 | 0.125 | 0.000 |
   | F1（早期入场） | 0.170 | 0.032 | 0.000 |

模型在打**低倍率的 B 级阵容**（终局板面里最高频的是 `永恒骑士`，B 级）。名次奖励管不了：
对 7 个引擎 bot 已经 1.18 名，**赢不需要 S 阵容**；`board_target` 只比"同回合战团总量"，
不区分"是不是同一个流派拼出来的"。所以需要一条直接对**流派**记账的奖励。

## 2. 口径

读 `config/strategy_cards.json`（33 个流派：S=5 / A=18 / B=10，49 张不同的核心卡）。
learner **每个回合起点**读一次战团卡 id，对每个流派算

```
得分_流派 = 等级权重(S=1.0 / A=0.6 / B=0.3) · min(1, 命中核心卡数 / max(2, 核心卡数))
```

取所有流派的**最大值**作为"本回合阵容完成度"，奖励 **本局历史最高完成度的增量**：

```
delta = coef · ( max_{τ≤t} 得分_τ − max_{τ<t} 得分_τ )
```

三条性质正好对上"不要机械照搬攻略、也不要只会固定套路"：

- **只认"拼成了什么"**：核心卡命中即得分，怎么买、怎么转、买哪几张都由策略自己决定；
- **转型合法**：用历史最高值而不是当回合值 —— 晚转型拼出更强的阵容照样拿分，
  中途卖光换方向**不扣分**（这也是和"势函数塑形"最大的区别：这里不惩罚过程波动）；
- **单局上界 = `coef`**，与名次奖励（终局效用 0..1）同量级，不会压过棋力信号。

细节：

- **只有 1 张核心卡的流派分母仍按 2** —— 否则"买到那一张"就能拿满分，
  奖励会退化成"抢某一张卡"的噪声；
- **`min_turn=8` 之前不打分**：更早的回合阵容还没成形，打分会鼓励为了凑卡乱买；
- **入场局注入的那一帧只设水位、不发奖励**（`set_floor`）：那一帧战团是真人库里塞进去的，
  白送满分会把尺度搞乱（`board_target` 踩过同一个坑）；因此这条奖励主要作用在
  **整局**那半边（`entry-p 0.5` 的一半游戏），这也再次说明混合课程是必需的；
- 卡 id 映射走 `hsbg_engine.card_info`，`player_json` 的 `Minion.card` 是 0-based
  CardId（高位是金色标记），所以取 `(raw & 0x0fff) + 1` —— 与
  `workflows/eval_two_models_six_bots.py` 的 `CardNames` 同一口径；
- `coef=0`（默认）时 tracker 不启用：不读状态、不写 record、不新增 meta 键，
  采集路径**逐位不变**。

## 3. 记账（必须能在 history 里看到）

`runlog.INJECTION_KEYS` 已登记 11 个 `comp_target_*` 键（这是 `board_target` 踩过的坑：
配了但没进 history，会静默跑完一整段）。`tools/analyze_entry_run.py` 对应输出三列：

- `c_best`：`comp_target_best_mean`（被评估回合的平均完成度，0..1）
- `cS%`：`comp_target_s_turns / comp_target_turns`（回合里"最优流派是 S 级"的比例）
- `c_rw`：`comp_target_reward_sum`（该轮的总奖励，量级应与 `t_rw`/`bt_rw` 相当）

`train_entity_sync.py` 启动期还会 fail-fast 打印流派库摘要
（`comps=33（S=5） cards=49`），库缺失/解析失败直接退出。

## 5. 两版给分口径的实测差异（2026-11-13 07:50）

| 版本 | 口径 | 实测 |
|---|---|---|
| v1（H1） | `min(1, hits/max(2,n))`，任一次命中就计分 | 训练内 `c_best` 0.133→**0.170**（在涨），但**面板覆盖零改善**（0.146，base 0.292）。原因：奖励被"只买一张核心卡"刷满 —— 0.17 ≈ 一张卡的分数 |
| v2（H2） | 加 `min_hits=2` 门槛，不足两张记 0 | `c_best` 稳定在 **0.085–0.106**（12 轮无趋势）。原因：面板实测"阵容完成度 ≥0.5 的局"只有 **3%**，门槛把奖励变成了稀有事件 |

**结论：两种极端都不对。** 正确口径应该是**按"增量"给分**而不是按"历史最高"给分：

> 对每个流派记录"本局已达成的最多命中数"，每当该数字**增加**就付
> `coef · tier_w · (Δhits / denom)`；每张核心卡每局最多付一次。

这样：买第 1 张也有分（但只付一次，不能反复刷）、买第 2/3 张继续有分（鼓励走到完成）、
完成时总付出恰好等于 `coef · tier_w`（上界不变）。实现属于 `comp_target.py`，
需要 digest 窗口（长训期间不能改），**排在长训之后**。
