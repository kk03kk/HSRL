# 37.0.3 战团库研究

研究分支为 `codex/hsrl-warband`，实验根目录为 `~/projects/HSRL/artifacts/warband/37.0.3-research-01`。NUS 计算节点生成库、采样、训练和评测。登录节点处理 Git、作业和清单。冻结起点为第一轮 PPO 的第 288 轮，源指纹 `9432249ae4888d0f`。战团环境使用单独的原生 wheel `e9f8f68e6fd3d0b0`。无战团模式通过旧轨迹的精确重放，运行期间不更换牌表、观测或动作编号。

## 素材与实现

| 素材 | 构建 | 留出边界 |
| --- | --- | --- |
| 原版与 V2.0 脚本 | 枚举十族中选五的 252 种牌池。保存确定性八人局各席的回合结束盘面 | 三份源局种子独立，源局和评测局种子段独立 |
| 冻结第 288 轮 | 在两种脚本对手的混合大厅经营。保存学习席回合末盘面及战斗所需的已知内部状态 | 独立三组源局，模型只作为离线素材生成器 |
| Firestone | 从压缩快照复读原始回放 ID、回合、可见站位、关键词和攻血。先把旧引擎卡索引还原为字符串 ID，再按 HSRL 卡表编码 | 按原始回放 ID 分组固定切分 60%／20%／20%。早期全量诊断单列 |

库按同回合和种族过滤。模拟轨迹采用精确牌池，真人视图按已观察的随从可兼容性投影。真人回放的交战对手视角会变换，所以真人库采用逐回合抽样。库文件中的承载序列只是分桶后的存储表示。独立回放 ID 是隔离单位，原始素材缺少所有上传视角共享的稳定大厅 ID。

战团在学习席与活跃脚本完成当轮招募后安装，再统一结算战斗。保持当前局的血量、护甲、淘汰和配对，内部场面的实体 ID 用本局分配器重映射。战团席启用后停止在共享牌池里补货，退回已有的持有副本，注入实体不占池。这个设计可以复用原生对局规则和合法掩码。由战团替代的席位不提供实时招募、共享池竞争和完整隐藏信息。正式观察和研究精度分别看实际强度、压力和跨场提升。

模拟库支持连续、重抽和仅脚本来源。连续方式沿着同一供体，缺同回合时改抽同牌池该回合的供体，累计换源次数。该牌池无对应回合时保留最后盘面，统计尾轮复用。严禁把尾轮复用比率高的面板当可靠的晚期棋力估计。

## 难度和训练方案

按原盘面的相对强度排序，保留弱、中、强三个有重叠的区间。连续轨迹使用 T7、T10、T13 的成长作为起点强度评分。重抽按当轮盘面排序。每个库都要用固定第 288 轮实测 T12 到达、前四、吃鸡和实际对局时长。首个入口优先让 T12 到达率至少 65%、前四至少 35%，再从可用档选择压力接近前四 65%、吃鸡 25% 的档。档位标签只用于复跑，不跨来源直接兑换。

比较纯脚本、75% 原脚本大厅加 25% 从 T8 启用三个模拟战团席、全程七席连续模拟战团、75% 原脚本大厅加 25% 从 T8 启用三个真人战团席。各臂从同一模型和 Adam 状态开始，独立重置训练随机数但共用对照种子，固定每轮 512 局、共 10 轮。参数探索另用独立训练种子、同一环境，比较固定学习率 7.5e-6 和 1.5e-5、熵 0.002 和 0.008、温度 1.0 和 1.2、关闭两道更新 KL 阈值。温度参与实际采样、更新和 logp 复算。固定 BF16 前向 512 行及同权重回放保护一直生效。终局效用不变，BC 固定锚点已在原阶段退火结束。

开发组选环境和参数，留出原局只用于固定候选。下一档继续用独立切片配对核验，检查旧脚本场名次和前四、留出真人战团效用、各档触底或饱和程度、逐回合运营、阵容配置及冻解异常。来源和档位分开记录，达到差异门槛后再提高占比或难度，一次只变一个维度。该方法适用于同补丁的模拟器评估。实机棋力另需真实对局。
